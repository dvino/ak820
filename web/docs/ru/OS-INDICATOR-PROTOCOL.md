# Протокол индикатора OS

Контракт реализует часть AKW-063 на стороне прошивки для разработки.
`AK820_OS_INDICATORS` управляет только **OS**; C и W сохраняют свои функции.
Отдельный `AK820_MAC_PC` задаёт обычное состояние OS. Без него оно выключено.

Desktop-helper и определение раскладки для разных ОС ещё предстоит реализовать.
До FD02 клиент определяет точный образ: VID/PID или произвольный ответ не
доказывают поддержку. [Каталог сборок](https://github.com/dvino/ak820/blob/v0.6.0-beta.2/web/docs/ru/CAPABILITY-CATALOG.md) готовит данные
идентификации, но не разрешает выпуск или запись.

## Обмен и запрос

Используется существующий 32-байтовый Raw HID. FD00, FD01 и USB-дескрипторы
не меняются. Новых Feature Report и GETFEATURES нет. Другую длину отклоняет
существующий обработчик USB.

FD02 не открывает транзакцию NVM и не сбрасывает данные на flash, в том числе
при неверном запросе или существующей ошибке NVM. Команда не разблокирует
Vial, не снимает ошибку хранилища и не подтверждает сохранение других настроек.

| Байт | Значение запроса |
| --- | --- |
| 0–1 | `FD 02` |
| 2 | Версия `01` |
| 3 | Действие: `00` чтение, `01` установка/подтверждение |
| 4 | Режим: `00` обычный/отмена, `01` выключен, `02` включён, `03` дыхание |
| 5–31 | Нули |

При чтении режим нулевой; чтение не продлевает срок. Неизвестные версии,
действия, режимы и ненулевые резервные байты отклоняются без изменения или
продления состояния. Истечение срока и отмена при разблокировке независимы.

## Ответ

| Байт | Значение ответа |
| --- | --- |
| 0–1 | `FD 02` |
| 2 | Версия `01` |
| 3 | Статус: `00` принято, `01` неверный запрос, `02` недоступно |
| 4 | Действующий режим после проверки срока и отмены |
| 5 | Маркер `A8` |
| 6–7 | Срок, little endian: `B8 0B` = 3000 мс |
| 8–9 | Период дыхания, little endian: `00 10` = 4096 мс |
| 10–31 | Нули |

Обычный режим означает правило, а не яркость: в Mac индикатор может гореть.
Установка требует владения тем же запросом, настроенного и бодрствующего USB
и отсутствия разблокировки Vial. Проверка, запись времени и режима выполняются
с сохранением и восстановлением маски прерываний. Отменённый запрос не может
заново включить управление.

Во сне или при разрыве связи ответ может не дойти. Тайм-аут считается ошибкой;
команда автоматически не повторяется. Клиент проверяет версию, маркер, нулевой
статус, режим, интервалы и резервные байты. Очередное подтверждение следует
после успешного обмена. Ошибка останавливает его до новой проверки соединения
и образа. Будущей версии нужен поддерживаемый разборщик.

## Время жизни

Состояние подтверждается каждые 1000 мс или чаще, без параллельных запросов.
Принятая установка даёт 3000 мс управления; чтение не продлевает срок.
32-битное время и окончательная отмена исключают возврат после 16-битного
переполнения или долгого макроса. Беззнаковая разность требует выполнения
основного цикла хотя бы раз за 32-битный оборот — примерно 49,7 суток.

Дыхание — треугольный цикл 4096 мс с шагом 16 мс и значениями 0–254;
постоянный свет использует 255. Подтверждение не сбрасывает фазу. Это
номинальные интервалы прошивки, не измерение физического устройства.

Приоритет: гашение при неактивном USB, действующее управление helper, затем
Mac/PC. Сброс, настройка USB, сон/пробуждение, истечение срока и разблокировка
Vial отменяют управление. Неизвестная раскладка, отключение и штатный выход
helper отправляют обычный режим; внезапная потеря связи отменяется по сроку.
Mac/PC сохраняется при очистке клавиш после USB/сна до перезапуска прошивки.

Helper уступает устройство настройке, обновлению и восстановлению (AKW-064).
Отмена в прошивке не заменяет исключительное владение и подтверждение операций.

## Каналы и доказательства

Заводское состояние OS поступает в слот 79, компонент 3, индекс DMA `0x13F`.
W использует компонент 1, `0x13D`; общая интенсивность находится в `0x13C`.
Она максимальна при активности любого канала, значения компонентов независимы.
Компонент 2 не меняется. C использует слот 71.

[Отчёт](https://github.com/dvino/ak820/blob/v0.6.0-beta.2/audits/rc6/web-firmware-20261024/README.md) содержит разбор
заводского кода и проверки точных образов. Они не доказывают физическое
подключение, яркость, реальное время или работу helper в ОС. Каждый профиль
сначала проверяет память, стек основной программы и IRQ, затем регрессии.
