# RC5: Tri Layer, GUI и проверки

Профиль включает стандартные QMK коды `TL_LOWR` (`0x7C77`) и `TL_UPPR`
(`0x7C78`). Первый временно включает слой **1**, второй — **2**. При
обоих активных слоях Tri Layer включает **3** (Adjust); при отпускании
одного из этих назначений пересчитывает и снимает Adjust.

В сохранённых исходниках штатного Vial GUI v0.7.5 и Entropy значения
называются `FN_MO13`/`FN_MO23`. В разделе Layers при ≥4 слоях присутствуют
кнопки **Fn1 (Fn3)** и **Fn2 (Fn3)**. Для AK820 с шестью слоями они доступны
по числу слоёв. Альтернативное назначение через Any: `0x7C77`/`0x7C78`.
Источник: `src/main/python/keycodes/{keycodes.py,keycodes_v6.py}` и
`history/original-work/vial-sources/vial-gui/src/main/python/keycodes/`.
Это проверка кода клиента, без взаимодействия с физической клавиатурой.

На выбранных Fn-позициях слоёв 1/2/3 удобно оставить `KC_TRNS`, чтобы
второе нажатие разрешалось в исходное назначение. Кеш RC5 также сохраняет
правильное отпускание, если активный слой скрывает уже нажатую позицию.
Стандартная карта остаётся прежней: функция назначается пользователем.

## Точная семантика слоёв

Пересчёт Adjust запускают только события специальных `TL_*`. Существующие
`MO(1)`/`MO(2)` сами по себе остаются обычными momentary layers: их сочетание
даёт биты 1+2 без автоматического включения 3. Для связанной пары назначать
оба `TL_*`; смешивание с обычными MO/TG не является глобальным правилом
«всегда пересчитывать слой 3 при любой смене слоя».

Используются обычные общие биты QMK. Два назначения одного Lower не имеют
счётчика владельцев: первое отпускание снимает Lower, даже если второе
назначение ещё удерживается. Другой toggled слой сохраняется; Adjust
является управляемым Tri Layer битом и пересчитывается также при unlock,
как на нормальном отпускании соответствующей Fn-клавиши.

## Что изменено

- `process_tri_layer.c`: две ветви выбора слоя используют один общий
  press/release/update хвост. Порядок вызовов и публичные getter API
  сохранены; нового состояния и сокращённой семантики не добавлено.
- `vial.c`: unlock распознаёт физически удерживаемые `TL_*` по исходному
  keycode cache, снимает их momentary слой и пересчитывает Adjust до
  подавления новых событий. Удерживаемые слои не остаются после unlock.
- `rules.mk`: `TRI_LAYER_ENABLE = yes`. Repeat уже исключает эти управляющие
  коды из истории при включённом флаге; Caps Word их пропускает.

## Свидетельства

Первый isolated image со штатным handler, но без TL cleanup: **39040 CODE**,
12 PASS / 4 FAIL. Все четыре FAIL — залипания после unlock, включая
сочетания с toggled или обычным MO слоем. После общего хвоста и cleanup:
**39012 CODE**, **16/16 PASS**. Это −28 байт относительно первого image,
несмотря на добавленное исправление; данное сравнение не является ценой
Tri Layer относительно выключенного движка на финальной базе.

Исправленный intermediate IHX:
`39c1de97f061b6ec8da3c73d62ade93475c43b32a300af01ac100c0d7e268d6c`.
Дополнительно на нём **17/17 Repeat/Grave Escape** и **10/10 unlock/remap**
проходят. Наблюдаемый максимум для Tri suite — **47 байт стека** без IRQ.
Root и code-size reviewer независимо повторили все 16 сценариев
и проверили diff перед включением.
Финальный `.build/rc5-release` повторно прошёл **16/16**; IHX SHA256
`1e3c61a4a1c7aeca4bfa74dea72865165c70710f8e20a0c4d27d0b58a9a66f78`.
Его наблюдаемый пик Tri Layer — **51 байт**, доступный стек **157 байт**
без вывода о полном IRQ/timing запасе. Финальный report находится в
`.build/rc5-final-feature-review/tri_layer/results.json`.

`measurements.json` и `reports/` сохраняют оба build reports, `.mem`,
отрицательный/исправленный runtime результат и дополнительные regressions.
`proposed-support.patch` фиксирует проверенный функциональный diff;
активные исходники содержат его изменения, вместе с дальнейшими правками.

Из корня QMK для выбранного связанного build:

```sh
python tests/ak820_tri_layer/run.py --build-dir /path/to/build --s51 /path/to/s51 --output-dir /tmp/tri-layer-results
```

Проверяются оба порядка нажатия/отпускания, одновременные события,
скрытие Fn активным слоем, live remap, unlock/cancel/reuse, сохранение других
слоёв, обычные MO, повторное Lower, Repeat history, paired virtual Vial
события и отпускание обычной клавиши после ухода с Adjust.
Runner проверяет, что все выбранные тестовые координаты входят в реальную
скомпилированную матричную маску AK820, а image лежит ниже NVM.

Это исполнение настоящего SDCC кода на generic C52. Matrix/NVM/готовность
USB endpoint — фикстуры; электрические параметры, Flash, реальный USB host
и IRQ timing этим не проверяются. Макросы, намеренно включающие виртуальный
слой без парного up, сохраняют существующий контракт Vial и не считаются
физически удерживаемыми Fn-позициями.
