# Release preparation source review

2026-10-26. Independent read-only review of `prepare_release.py` and `capture_settings_tests.py`, including their calls into settings validation, measured catalog generation, source snapshots and release-safety validation. This review covers source contracts only. Fresh ten-profile builds and final policy outputs were not available for qualification.

## Findings and closure

1. **P1: frozen beta.2 rows are still validated as current profiles.** `prepare_release.py:235` calls `_catalog_images(old)` before moving those rows into `historical_profiles`. Current MAIN includes Auto Shift; beta.2 MAIN does not. The supplied frozen catalog therefore raises `ValueError: Build configuration differs from the selected profile` before any new build is measured. The same incompatible catalog is passed into historical build/bundle loading at lines 314–316. Construct a separate source-only view of the frozen catalog for validation and historical loading, with no historical target edges, while retaining the original frozen file unchanged. Reproduction used the actual frozen `historical-catalog.json` and current settings reader; no input mutation was needed.

2. **P2: the frozen settings run omits extension regression tests.** `capture_settings_tests.py:29` selects `test*settings*.py`. This runs the catalog, core backup and settings-workflow modules, but excludes `test_extension_backup.py`. Its three schema03 roundtrip, inactive-module and downgrade tests belong to the settings contract being qualified. Include that module in the captured run and keep the source snapshot and log binding around the complete run. File-pattern enumeration confirmed the omission without executing the capture script or replacing existing evidence.

3. **P2: valid older backup manifests without scope cannot enter the transition matrix.** `prepare_release.py:343` reads `backup['manifest']['scope']` directly. The validated backup format permits scope to be absent, including synthetic legacy fixtures. A correctly validated source backup can therefore fail later with `KeyError`, despite satisfying the documented source-backup input contract. Preserve supplied scope when present and use explicit unknown/supplied-backup provenance when absent; do not infer live getter evidence.

All three findings were corrected and independently rechecked on 2026-10-26. The frozen input is now deep-copied into `source_catalog`, its old rows become historical rows, its current rows and transition edges are empty, and both historical loading branches use that view. An independent execution of this transformation accepted all 13 frozen images with current AS MAIN and retained old MAIN getter IDs `[1, 2, 7, 18, 19]`. The capture pattern is now `test*.py`, which includes the extension module and the rest of the installer suite. Missing scope uses `Validated saved backup; capture provenance not recorded`, preserving the evidence boundary. No actionable findings remain in this source-only review. The broadened captured suite itself was not run by this reviewer.

## Confirmed source properties

The new-image loop uses the curated ten names and freshly calls `measured_row`. That path inspects current configuration, compiler inputs, artifact identity, linked memory, runtime component hashes and qualification evidence. It consequently rejects an old MAIN build presented as the current Auto Shift MAIN. The subsequent policy loop covers the same ten names in three fixed groups.

Packing uses validated private OEM inputs, checks permanent/trial payloads, and compares permanent CODE with the freshly measured settings identity. Private output must be a new directory outside the repository. The draft catalog preserves typed historical rows and pinned legacy sources, creates source-to-current transition edges, validates the combined catalog, and requires supplied/default fixtures to cover every retained source identity. Caps Word Combo and macro Layer-Tap cross-current-profile plans are exercised separately. These are offline plans, not actual restore evidence.

Policy construction binds IHX, normalized symbols, schema, current configuration, host-file hashes, build source paths, runtime checker sources, copied stack/startup/IRQ witnesses and transition witness hashes. Settings records are checked before preparation and again after catalogs are installed, so changed tested catalog bytes are rejected. The policy source set also includes the preparation script and the captured test sources. A stale build cannot be qualified merely by replacing its reported MAIN label because the measured inspection checks configuration and build inputs.

No independent approval or physical validation is generated. Outputs explicitly record `independently_reviewed: false` and hardware/device limits. The script opens no device. Successful source inspection does not approve the future generated policy manifests; their exact source, catalog, evidence and witness hashes still require independent review after correction and source freeze.

No implementation, catalog, policy, log or approval files were modified by the reviewer. Only this report was written. Future generated policy outputs still require exact-output review.
