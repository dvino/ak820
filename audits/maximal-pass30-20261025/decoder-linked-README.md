# Linked default-keymap decoder CPU proof

The exact enabled image and OFF control pass 275 calls each: all 256 valid default-keymap locations and 19 invalid locations. Invalid calls cover layers 2–6, 127, 254, 255; rows 16, 17, 127, 254, 255; columns 8, 9, 127, 254, 255; and all axes 255. Every invalid result is KC_TRNS (1). The six-layer dynamic reset loop therefore has its absent default layers 2–5 covered. Results record DPL, DPH, SP and a two-byte IRAM canary for every call.

`summary.json` binds the two image hashes. `accepted-shard-0` through `accepted-shard-3` contain final results and full simulator logs. Each shard loads both exact images and verifies every occupied CODE byte against IHX before and after execution, using explicit `dump /h rom`. Encoder-map 8 bytes and LED-points 164 bytes match the control through direct reads from parsed linked CODE. Current bootstrap keymaps (512 bytes), generated tables and their linked addresses match. Generation inputs and manifest, simulator, support tools, source, map, ASM, RST and runner hashes are retained and checked unchanged.

The actual SDCC raw-getter ABI comes from current emitted ASM and linked symbols: layer in DPL, two one-byte parameters in their linked XRAM locations, word return in DPL/DPH. CRT runs only to main entry; main does not execute. IE and IE_EX are disabled. No NVM is seeded. Flash/read/write entry breakpoints and ROM_STATUS access guards stop unexpected backend activity. Only the verified empty simulator trampoline 0x2600–0x26ff permits simulator ROM writes. No device or network is accessed.

`keymap_layer_count_raw` has been removed by DCE in both exact images, so an actual call to that nonexistent entry cannot be tested. The current bootstrap metadata and the linked raw-getter bound establish two raw layers. This is static evidence, not a fabricated CPU invocation.

For the 256 valid calls, the decoder adds 42,260 instructions and 706,464 generic C52 ticks in total. Per-call deltas range from 14–318 instructions and 276–5,256 ticks. The identical trampoline overhead cancels in the difference. This measures only the default lookup component used during reset; it does not measure complete reset, CH555 timing, an 11 ms comparison, or ordinary keypress latency. The VIA getter continues to use the dynamic NVM path; this codec branch changes the raw default getter only.

Reproduction uses `python3 run.py --repo REPO --build ENABLED_BUILD --control OFF_BUILD --output OUTPUT --shard-count 4 --shard-index N`. `launch.sh` records the local pinned-container execution with read-only source/build mounts and a writable external evidence directory. Docker image identity is `sha256:b41196ff4098d5b33786f23238a17ad1fb21b943a588076e085c4881e920d97d`. Generic C52 CPU execution does not prove CH555 peripheral, durable-storage, interrupt, full-image regression or physical behavior.

`attempt2` is an exploratory successful shard from before instruction-delta collection and is excluded from accepted aggregation. The initial attempt failed before simulator startup because the generator helper import path was absent. It produced no accepted CPU evidence. Independent review remains a separate acceptance gate.
