## Independent verification

All original SHA256SUMS and every source-hashes.json entry matched. Reproduction ran in `default-keymap-review-rerun/prototype`, with the repository mounted read-only and networking disabled. The original prototype was not changed. Both generated candidate C files, the baseline, resolved bytes and all three component REL files reproduced byte-for-byte. Native ASan/UBSan comparison passed all 16,777,216 uint8 triples for each representation. Six real decoder mutants failed as expected. Both separate-translation-unit SDCC/s51 runs passed all 256 defaults, 1024 boundary/invalid tuples and raw-count checks. The baseline instruction comparison with the existing pass29 assembly passed. These are component and CPU-model checks, not full-image checks.

The 512-byte table is the resolved current pinned pass29 table; run.py checks its IHX binding. The baseline uses the exact source getter body rather than a different indexing expression. Explicit CODE-qualified arrays generate MOVC access. The independently reproduced REL totals are 595 baseline CODE / 3 XDATA; 394 class CODE / 6 XDATA; 532 marker CODE / 7 XDATA. The class component gain is 201 CODE bytes at a cost of 3 XDATA bytes. The standalone register-bank declarations and XDATA costs do not establish final linked overlays or stack capacity. SDCC ignores -Os as documented.

For the exact 2 x 16 x 8 input, bounds checks precede table reads and invalid coordinates return KC_TRNS=1. Row indices are 0..31, class indices 0..63, payload offsets 0..106 and total payload size 114. Prior-entry skips and a final two-byte read remain within the payload; no uint8 position wraps. Classes preserve KC_NO, KC_TRNS and all 16-bit values. This proof does not permit arbitrary future dimensions or larger payloads without generator validation.

The source has one production raw-getter consumer: dynamic_keymap_reset. The ordinary VIA getter calls dynamic_keymap_get_keycode and reads six-layer 16-bit NVM storage; it does not call this decoder. The non-VIA weak wrapper does call the raw getter and can lie on a keypress path; compression must remain disabled there. Reset/startup timing remains a separate performance qualification. The existing assembly separately contains exactly 8 encoder-map bytes and 164 LED-point bytes; neither table is part of this prototype. Encoder layer equality, six-layer NVM offsets, big-endian wire values and ordinary keymap reads must remain unchanged in integration.

## Smallest maintainable automatic integration

Do not ship the pinned IHX word list or use a C-expression evaluator on preprocessed source. The compiler already resolves layouts, aliases and constant expressions. Prefer one small build step around the existing introspection translation-unit compile:

1. Gate the feature on the exact AK820 SDCC large-model VIA/Vial configuration and intended keymap. Keep option-off, non-VIA, other boards and other keymaps on the original source branch. Unsupported explicitly enabled configurations fail closed.
2. Bootstrap-compile the current original introspection TU to assembly using the same includes, defines, flags and compiler as the final TU, with one private extraction-phase macro. In that phase retain the original keymaps definition and sizeof assertions. No bootstrap link or full firmware build is needed.
3. Extract only literal bytes from the named `_keymaps` CONST block. The observed compiler emits literal `.byte #0xNN, #0xNN` entries and an area boundary. Reject missing/duplicate symbols, expressions, relocations, unexpected directives/areas, odd byte counts and unsupported toolchain output. Obtain dimensions/count from compiler-resolved metadata or an equally strict metadata block, not an inferred hardcoded old layer count.
4. Generate one include with class, payload and row-offset arrays declared in CODE, the raw layer count and source/tool/command digest. Require 16 rows, 8 columns, the validated two raw layers, 16-bit words, all data/indices fitting their declared widths, and KC_NO/KC_TRNS assumptions. Validate every row end, every payload advance and the complete decode against all resolved words before writing output atomically. Reject payloads beyond the uint8 representation; do not truncate offsets.
5. Final-compile introspection using that generated include. Only this final gated branch suppresses the original keymaps allocation and substitutes raw getter/count. The encoder_map and LED definitions remain included normally. Existing encoder/raw layer equality and maximum-layer assertions must operate on the generated count. Use generated array-length assertions as well. No change to dynamic_keymap.c, NVM or protocol is required.

A hash beside an include does not by itself prevent stale output. Run bootstrap/generation as a prerequisite every time this TU is compiled, or use complete compiler dependency files plus command/compiler identity as dependencies and verify their digest before final compilation. The final TU must depend on the generated include. Source changes during generation must cause failure/retry before acceptance; parallel profile builds need separate output directories. The bootstrap object must never enter the link. Do not create a circular dependency from bootstrap to the generated include.

A direct compiler-assembly rewrite could avoid a second compile, but then must correctly replace data, functions, symbols, debug metadata and area sizes. That expands the transformation contract for a 201-byte component gain and is not recommended. If the existing builder cannot express the narrow bootstrap step cleanly, keeping the original 512-byte table is preferable to a complicated generic generator.

## Mechanical gates for a later patch

- Rebuild generated bytes after changing a keycode to a high 16-bit constant, KC_NO and KC_TRNS; show changed decoded output. Prove stale include, missing generator, dependency/flag/tool change and unsupported dimensions/count/payload fail closed. Test clean and incremental builds.
- Repeat current component comparisons and independent exact-patch review. Option-off and non-VIA paths must reproduce the original getter/table; generated constants must match the current bootstrap table, with original keymaps absent only from enabled final output. Compare encoder and LED bytes independently.
- Revalidate the builder input manifest and certificate identity after any build-tool change. Protected board/timer/USB/map-runtime modules remain unchanged, but their previous spill certificate cannot silently certify a changed build pipeline.
- Qualify final linked CODE/XDATA, stack and all enabled interrupts for that exact image before broader regression, following repository policy. Record reset/startup latency independently. Ordinary keypress source routing is established here; physical responsiveness is not.

No production source/build changes, main firmware builds, Git writes, network access or device operations were performed in this review.
