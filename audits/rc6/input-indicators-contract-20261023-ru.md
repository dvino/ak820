# Caps, смена языка и индикаторы


Проверка остановлена до изменения прошивки. Базовая версия — `5887e92`.
Сборки кандидата и проверок на клавиатуре нет. Файлы выпуска не менялись.

Для смены языка предлагается Win+Пробел и отдельный переназначаемый код на
месте Caps. Обычный Caps Lock должен остаться доступен в Vial. Любой Shift
вместе с новым кодом должен выдавать Caps Lock без Shift. Отпускание клавиши
не должно повторять действие, а Repeat не должен запоминать смену языка.
Сохранённую раскладку нельзя сбрасывать ради нового значения по умолчанию.

Простой вызов tap_code не подходит. Если Пробел уже удерживается, он создаёт
повторное нажатие и затем снимает чужое удержание. Для уже удерживаемого Caps
возникает та же проблема. Нужно заранее выбрать правило: отложить действие до
отпускания мешающей клавиши или пропустить это нажатие. Для отложенного
действия нужны правила очереди, отмены, тайм-аута и разблокировки Vial.

В USB сохраняется только последний ожидающий отчёт. При тайм-ауте следующий
отчёт может заменить ещё не переданное нажатие. Поэтому нужен механизм,
который сохраняет каждую стадию нажатия и отпускания до её передачи.
Одной задержки между отчётами недостаточно для доказательства.

Состояние Caps от Windows уже доступно. Но адреса и полярность физических
индикаторов C и W в текущем исходном коде не установлены. Неиспользованные
светодиодные слоты нельзя назначать им наугад. Сначала нужна проверенная
схема или разбор соответствующего участка заводской прошивки.

C должен показывать реальный Caps Lock. W должен гореть при активном
дополнительном слое и гаснуть на основном. Будущий Windows-помощник должен
получать реальный язык активного окна; считать нажатия Caps нельзя.

## Предлагаемая реализация

Следующий вариант должен передавать действие по стадиям: дождаться отпускания
мешающей клавиши, передать модификатор, нажатие, отпускание и затем текущий
физический отчёт. Следующая стадия начинается только после принятия предыдущей
USB-транспортом. Это ещё не доказывает, что Windows выполнила переключение.
Нужен ограниченный тайм-аут и безопасная отмена. После уже переданного
нажатия отмена всё равно должна передать отпускание.

Ожидающие действия следует отменять при разблокировке, USB-сбросе и связанном
переназначении. Обычные запросы Caps следует объединять, но точный результат
такого объединения нужно определить до реализации. Простое удаление очереди
после переданного нажатия может оставить клавишу зажатой.

Нужны проверки обоих Shift, всех удерживаемых модификаторов, уже удерживаемых
Пробела и Caps, изменения модификаторов в очереди, переназначения, разблокировки
Vial и сброса на каждой стадии. Отдельно нужны тайм-аут каждой USB-передачи,
Repeat/Alt Repeat, полный 6KRO-отчёт и NKRO. Полный список случаев и места
в исходном коде приведены в [английском отчёте](input-indicators-contract-20261023.md).

Проверки событий пока не добавлены: реализации кандидата и полного принятого
правила обработки событий нет. Это план проверок, а не результат тестирования.
