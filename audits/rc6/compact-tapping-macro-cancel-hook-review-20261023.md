# Macro cancellation fixture review — 2026-10-23

The corrected fixture is approved for the scoped linked CPU cancellation check.
No blocking finding remains. The review covers `macro_cancel_case` in
`qmk-8051-ak820/tests/ak820_tapping/emitted.py`, its linked-test README and
`compact-tapping-macro-cancel-diagnosis-20261023.md`.

The existing IHX has SHA-256
`24e97578ee469e5343d6949976fef96898d87c0e38ec6148374af1b1611a1655`.
The relocated listing identifies 0x8D6F as the SS_DOWN call to
`register_code` at 0x74F6. Its surrounding instructions save and restore
r7/r6/r5. The fixture requires exactly one matching sequence before replacing
`12 74 F6` with `12 26 40` in simulated ROM.

The 59-byte hook occupies 0x2640..0x267A. Its generated bytes call the original
register function first, save 13 direct registers, call `clear_keyboard` at
0x7682, restore those registers in reverse order and return. This preserves
the state that the unmodified register call would leave for its caller.
The original caller still restores r5/r6/r7. The hook deliberately retains the
clear's memory changes, including the cancellation flag. Stack pushes and pops
balance. The extra call depth belongs to the fixture.

The listing maps ar0..ar7 to direct bank-0 addresses. Direct register saves
remain valid for this CRT-initialized, non-interrupt CPU case. They do not
establish operation with another register bank or nested interrupts. The
hook checks reject overlap with loaded image bytes and the call trampoline or
stop. The normal runner also checks the reserved ROM area before running.

An independent execution of only `macro_cancel_case` passed. Evidence is in
`qmk-8051-ak820/.build/compact-modtap-cancel-hook-review-20261023/`:
`results.json`, `macro-cancel-stops-stream.sim` and its `.log`. All eight
snapshots, five keyboard reports and two consumer callbacks matched. The
macro used 263,328 emulator clocks. Peak SP was 136 from initial 101, including
the hook. The second macro DOWN did not execute; release followed by a fresh
B press and release succeeded.

The documentation agrees with the fixture and the scoped result. The original
65-case run remains failed. No complete corrected suite was run during this
review. No production source or firmware image was changed, no firmware was
built and no device was opened. This approval establishes no EE_CLR, reset,
NVM persistence, USB, physical input, interrupt overlap or physical timing
result. Those boundaries remain open rather than being treated as passed.
