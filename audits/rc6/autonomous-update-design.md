# Обновление без отдельного Vial

Проверка исходников от 2026-10-23. USB не открывался. Прошивка и готовый кандидат не менялись. Это проект действий программы, а не результат проверки на клавиатуре.

Владелец уточнил порядок: нажать «Обновить», удержать Esc + левый Ctrl три секунды, затем программа сама переводит клавиатуру в загрузчик, записывает образ и проверяет его. Ввод `yes` и отдельный Vial для этого порядка не нужны. Удержание клавиш остаётся осознанным подтверждением владельца.

## Что уже есть в исходниках

`qmk-8051-ak820/quantum/vial.h` задаёт команды FE05, FE06, FE07 и FE08. Все пакеты имеют 32 байта; неиспользуемые байты запроса равны нулю. `Application.raw()` добавляет нулевой report ID только для HID-записи; в ответе его нет.

| Запрос | Ответ и действие |
| --- | --- |
| FE05 | Байт 0: разблокирована; байт 1: разблокировка начата. С байта 2 идут пары строки и столбца; незанятые байты FF. |
| FE06 | Начинает отсчёт заново. Ответ повторяет запрос; это не доказательство завершения разблокировки. |
| FE07 | Байт 0: разблокирована; байт 1: разблокировка начата; байт 2: оставшиеся такты удержания. |
| FE08 | Снимает разблокировку и отменяет её ожидание. Ответ повторяет запрос. |
| 0B | VIA Bootloader. Требует `vial_unlocked`. Даже отклонённый запрос может вернуться таким же пакетом. |

`quantum/vial.c:vial_unlock_task()` измеряет непрерывное удержание по физической матрице. Отпускание любой клавиши начинает отсчёт заново. Опрос компьютера не заменяет физическое удержание. В `keyboards/ajazz/ak820/config.h` заданы позиции (0,0) и (0,5).

`tmk_core/protocol/ch555/usb_ak820.c:raw_request_is_nonpersistent()` разрешает ответы на эти команды при ошибке хранения. Это не снимает проверку Vial. `ak820_boot.c:bootloader_jump()` стирает маркер по 27C0 и проверяет чтением нулевые четыре байта; только потом сбрасывает контроллер. Подтверждение 0B отправляется раньше этой проверки. Поэтому подтверждение пакета не доказывает переход в загрузчик.

## Изменения только на компьютере

В `tools/installer/ak820.py:update_prepared()` сохранить проверки релиза, полного свежего ROM, личной копии и точных хешей. Заменить ввод `yes` и инструкцию об отдельном Vial на встроенную разблокировку. Не менять замороженный кандидат и `UPDATE_PINS` в `qmk-8051-ak820/util/ak820_tool.py`.

После выбора операции проверить ту же клавиатуру и FE05. Чтобы старое состояние unlocked не заменяло новое согласие владельца, один раз отправить FE08, проверить FE05=locked/not-in-progress, затем один раз FE06. Проверить FE05=in-progress. Показать просьбу об удержании. Опросить FE07 с ограниченным временем, без повторов неудавшихся обменов. Продолжать только после полного корректного ответа unlocked=1, in-progress=0, counter=0. Непосредственно перед 0B повторно проверить состояние и выбранное устройство. Один раз отправить 0B. Затем ждать ровно один подходящий загрузчик и проверить его идентичность существующими средствами. Только после этого использовать существующие ограничения erase/flash/checksum/restart/readback.

Обычная отмена до 0B может один раз послать FE08 и проверить FE05: это завершение начатой пользователем разблокировки, а не восстановление настроек. Это действие должно быть явно включено в разрешённую операцию. При тайм-ауте HID, повреждённом ответе или неожиданной ошибке хранения остановиться без дополнительного FE08, повторов, сброса или восстановления. Отдельно сообщить, что разблокировка могла остаться активной. После 0B не считать отмену доказательством остановки устройства; никаких новых команд без установленного состояния.

Установленная ошибка хранения уже известна и допускается только как точное исходное состояние этой подготовленной ремонтной пары. Новая ошибка, другой снимок или другая стадия должны останавливать операцию. Успешное обновление доказывают появление приложения, чтение кода, сравнение защищённых областей и проверка хранения, а не один ответ загрузчика.

## Проверки перед выпуском программы

Расширить `tools/installer/test_prepared_update.py` и `test_installer.py`: полный порядок FE08/05/06/05/07/05/0B; свежее удержание при ранее unlocked; отмена; отсутствие удержания; некорректный счётчик; короткий ответ; тайм-аут каждого обмена; подмена пути; неоднозначное устройство; ответ 0B без загрузчика; ошибка проверки маркера; отсутствие повторной прошивки и автоматического восстановления. Модели не доказывают физическое удержание и переход конкретной установленной прошивки.

Обновить `tools/installer/gui.py`, проверки интерфейса, README.md, docs/STATUS.md и русские инструкции. Пересобрать выпуск программы из того же кандидата через `tools/build_release_bundle.py`; обновить файлы выпуска, manifest и `tools/installer/approved-release.json`. Проверить хеши вложенной прошивки и личного образа: они должны остаться прежними. Проверить новые хеши программы и получить независимый обзор кода, документации и результатов до коммита. Запись на клавиатуру требует отдельного разрешения владельца для этой операции; исходники сами по себе не подтверждают поведение установленного образа.
