# Combos and memory reduction

The development image fits with eight configurable two-key Combos and every
previously enabled function. Grave Escape and NKRO remain enabled. Six layers,
sixteen macros with 8192 shared bytes, compact Mod-Tap/Layer-Tap, Caps Word,
Repeat/Alt Repeat, Tri Layer, RGB effects, RAM-only Direct and C/W indicators
are retained. No keyboard was accessed, flashed or reset during this work.

The immutable source control is `4b83bb9`. The work branch is
`dev/compact-combos-20261024`. The published and installed
`v0.6.0-alpha.1` remains separate; this candidate has not been promoted to the
installer or published as a release.

## What created room

The first complete Combo implementation added 2341 bytes. The same eight-entry
contract was reduced to a 1779-byte addition before integration. The final
isolated Combo probe used 42,256 bytes and crossed the real main boundary.
Those enlarged-window builds were measurement tools only. None is a usable
firmware candidate. See the [Combo probes](compact-combo-probes-20261024.md).

The retained changes are:

- Exact repeated instruction blocks now include short, profitable sequences
  and an explicit set of foreground modules. The final image has 150 helpers
  at 1525 sites. Helpers contain the original instructions and one return;
  they cannot nest and add two transient stack bytes. PC-relative loads,
  branches, calls, stack operations and arbitrary direct/SFR accesses remain
  excluded. USB control/interrupt code, IAP, board IRQ and delay code remain
  outside the added scope.
- Target-only SDCC `noinvariant` pragmas keep selected loop expressions local.
  They are guarded by the AK820 target and pinned compiler; low-window macro
  code is not given the pragma.
- HID report helpers use the proved XDATA report buffer internally, keeping
  the public generic pointer signatures. `process_action` snapshots only the
  pressed flag that it actually reads. Default and ordinary layer actions
  share mask calculation while retaining their different setters and owners.
- USB dispatch shares request selection and stable predicates. Descriptor
  pointers retain their CODE address space. RGB removes overwritten defaults
  and uses equivalent bounded age arithmetic.
- Separate XDATA EEPROM APIs serve proved local/global/Raw HID buffers.
  Generic APIs remain in source. Scalar byte reads share the original offset
  logic. Two parser structures copy their two meaningful byte fields.
- Combo validation, matching and reload avoid repeated checks while retaining
  request validation, marker validation, verified journal flush and fault stops.

The last integrated measurement before the expanded outliner used 41,045
bytes. The exact final outlining transformation reduced that image by 732
bytes to 40,313. Isolated savings do not necessarily add after compilation and
linking. The [compiler report](compiler-outline-20261024.md) and
[protocol report](protocol-optimization-20261024.md) retain individual controls,
negative results, pointer provenance and verification limits.

Rejected probes include a larger CRC rewrite, scalar word/write variants,
ordinary bool USB predicates with higher internal-RAM cost, broad compiler
flags and extra record pointer aliases that saved only two bytes. Invalid
early builds are retained as failures in the summary and are excluded from
measurement comparisons. Grave Escape and NKRO removal were unnecessary.

## Verification

The new host engine/storage tests pass, and the production tapping fixture
passes configured Combo cases and all 156 retained-QMK HID comparisons.
The [linked Combo report](combos-20261024/combo-linked-results.json) passes 26
cases against the exact candidate IHX. It covers 6KRO/NKRO, timing and wrap,
interruption, output owners, Repeat, Caps Word, cancellation and actual Vial
packet dispatch. The valid setter case writes an identical record and proves
successful cache/reload behavior without programming flash.

The [callee report](combos-20261024/callee-results.json) passes all 2674 cases.
Its fixture now compares returned SP with the observed post-CRT entry SP.
The old fixture incorrectly compared against the linker SP seed even though
the CRT call into `main` already occupied two bytes. That initial failure and
its isolated correction remain in the protocol evidence. The test still
requires every selected register, return value, memory effect and SP to match.

The [complete qualification](combos-20261024/qualification.json) passed all
28 suites and 258 unit tests, without skips. IHX and MAP stayed unchanged
before and after every suite. The first attempt is preserved as
`qualification-initial.json`: 27 suites passed, but the existing macro-clear
fixture required a register-save pattern that the new code generation removed.
The corrected locator requires a unique actual DOWN call in the production
function, checks ASM/RST agreement and the linked call bytes, then uses the
same register-preserving trampoline and output assertions. All 65 tapping
cases and the complete repeated qualification pass. Firmware bytes did not
change to resolve this fixture issue.

The [exact-outline CPU report](combos-20261024/outline-results.json) verifies
all 150 helpers and 1525 replacement sites, with sixteen states per helper.
The independently linked test image and normal build have identical IHX and
selected helper groups. All eleven outliner safety unit tests pass. Each
helper adds two transient stack bytes; no helper calls another helper or an
original C function, and newly eligible functions are outside IRQ call paths.
The largest observed foreground use in the combined suites is 61 of the 160
allocated bytes. This is a tested-path observation, not a whole-program or
physical interrupt-overlap upper bound. ASan and UBSan remain enabled in the
applicable host fixtures; LeakSanitizer is disabled because this environment
cannot enumerate process metadata.

The added helper call/return has a runtime cost. Generic C52 samples measured
about 0.2% more clocks for macro execution, 5.1% for matrix/Fn processing and
5.8% for RGB/Direct/suspend processing against the same integrated source with
the narrower outliner. These are simulator instruction-clock comparisons,
not VS11K28A wall time, USB latency or physical scan measurements.

No host or CPU result proves electrical IAP behavior, physical USB/IRQ timing,
GUI handling, power-loss durability or cold-start retention. These checks and
the existing native Windows acceptance remain open.

## Settings and release boundary

[Combos](../../docs/COMBOS.md) documents the eight two-key entries and fixed
40 ms term. The base schema remains `0x082002`; an explicitly marked version-1
extension occupies `0x0658..0x06a7`. Every ten-byte entry stays within one
64-byte journal page. Missing/invalid markers are read as empty without writes.
The journal format, verified write order and latched failure behavior remain.

The pinned installer backup does not export this new extension and does not
accept this candidate image. A future release needs an explicit Combo backup
and migration contract, fresh artifact review and packaging. No exact-image
pin, approved bundle or live update workflow was silently changed.

[Independent review](combos-20261024-review.md) approved the source, normal
application build and evidence for development commits and the Git archive.
No blocking finding remains. Installation, release promotion, physical
acceptance and Combo backup migration are outside that approval.

The final [source binding](combos-20261024/source-binding.json) verifies all
470 build inputs. All 429 tracked source inputs match the implementation
commit, and the retained IHX, MAP, MEM and build report are byte-identical to
the reviewed normal build.
