# Contributing

Start with the [build](docs/BUILD.md), [development](docs/DEVELOPMENT.md) and
[testing](docs/TESTING.md) guides. When reporting a problem, name the keyboard
variant and firmware hash, and give the steps that reproduce it. Say whether a
result came from a model or from trying it on a keyboard.

Keep each change focused. If code changes how something works, update the
English guide and its Russian translation with it. In a pull request, list the
checks you ran and what you could not check. Changes to image packing, startup,
USB, saved settings or function calls need checks at those boundaries and a
review by someone else.

Do not include personal ROM backups, private captures or local recovery
sessions. New original contributions are offered under GPL-3.0-only. Keep the
license notices that belong to other projects; see [licensing](docs/LICENSING.md).
Before writing firmware to another person's keyboard, get that person's approval.
