# Автономная проверка стека

`configure_firmware.py check-runtime` проверяет, хватает ли внутренней RAM для стека основного кода, пути запуска и обработчиков прерываний. Проверяются точный образ и файл карты из существующего каталога сборки; прошивка не пересобирается, связь с клавиатурой не используется.

Запустите команду из корня репозитория:

```sh
python tools/configure_firmware.py check-runtime \
  --build-dir qmk-8051-ak820/.build/candidate \
  --toolchain toolchains/sdcc-4.6.0
```

Команда завершается успешно, только если для всех нужных путей известны границы, а их общий предел помещается в стек связанной прошивки. Ошибка означает, что доказательств нет, они противоречат друг другу, какой-то путь не удалось ограничить или память превышена. Подробности находятся в `runtime-safety/summary.json`, соседних отчётах и журналах. Хэши образа, карты, проверяющих программ и доказательств не позволяют применить результат к другой сборке.

Каждый новый профиль или образ исходников должен пройти эту проверку до остальных регрессионных тестов. Сборка завершается ошибкой, если нужную границу определить не удалось или превышена ёмкость стека. `check-runtime` повторно проверяет доказательства существующей сборки.

Расчёт начинается при входе в C runtime с `IE=IE_EX=0`, как задаёт упаковщик, и включает постоянный кадр вызова при входе в `main`. Эта предпосылка является частью доказательства; пробное стирание до CRT в неё не входит. Расчёт предполагает корректный доступ C к памяти, ABI SDCC с банком регистров 0 и правила обработки прерываний MCS-51. Обёртки прерываний сверяются с закреплённым общедоступным набором инструкций. Этот набор не подтверждает идентичность подключённого устройства.

Это статическая проверка и данные модели CPU. Она не измеряет реальное время выполнения и не доказывает поведение при физическом стирании памяти, потере питания или работе устройства. Исходный код, результаты CPU-модели для связанного образа и поведение установленной или выпущенной alpha.3 — разные сведения. Проверка относится только к точному образу из отчёта. Результат не разрешает выпуск или смену настроек. Отчёт и независимая проверка приведены в [техническом аудите](../../audits/rc6/web-firmware-20261024/runtime-all/README.md).


## Охват целого образа

Основной корень — `_main`, со всеми достижимыми вызовами, которые нужны
включённым функциям. Запуск проверяется отдельно, включая кадр, оставшийся
в стеке после вызова `main` из CRT. Включены три источника прерываний: USB,
таймер и LED. Их обёртки и обработчики учитываются для всех 15 порядков
вложения разных источников. Неизвестный необходимый вызов или поведение IRQ
блокируют проверку. Общая граница сравнивается с ёмкостью стека из MAP/MEM
этого образа, а не со значением другого профиля.
