# Палитра Direct

Direct хранит 82 цвета HSV8: оттенок, насыщенность и яркость задаются байтами.
Индексы соответствуют светодиодам Vial (`GET 0x44`), а не 83 физическим клавишам.
Яркость ограничена значением 160. Палитра находится в RAM и пропадает при
отключении питания. При выключенной подсветке чтение возвращает сохранённые
цвета, а не чёрный кадр.

Нужны точный образ с проверенным контрактом Direct v1 и согласование возможностей
с устройством. У старых образов и профилей без Direct чтение недоступно. Общий
цвет RGB не позволяет восстановить палитру. Старый fastset сразу меняет до девяти
светодиодов; последовательность таких пакетов не является атомарным кадром.

## Вызовы на компьютере

`DeviceAPI.direct_snapshot()` читает согласованную палитру. Если расширение
недоступно, возвращается `None`. При смене поколения чтение начинается заново,
но выполняется не более трёх попыток. Ошибка или неверный ответ останавливает
вызов. Снимок включает флаги последнего чтения состояния. Они описывают видимость
в этот момент: включение, выбор режима и suspend не меняют поколение палитры.
Сохранённые цвета читаются и при погашенной подсветке. Чтение не меняет режим, подсветку, блокировку Vial или EEPROM.

`set_direct_frame(hsv, frame_id=…, expected_generation=…)` требует экземпляр с
`allow_writes=True`. Передаются 246 байт, ненулевой 16-битный номер кадра и
поколение свежего снимка. Клиент ограничивает каждый байт V значением 160 до
начала передачи и сохраняет переданный объект bytes без изменений.
Цвета загружаются последовательно, до восьми за пакет,
после чего выполняется commit. При ошибке нет автоматической отмены, повтора или
восстановления. `direct_status()` читает состояние; `direct_abort(frame_id)` явно
отменяет соответствующую незавершённую загрузку. Эти вызовы не дают разрешения
на запись в устройство.

Успешный commit заменяет логическую палитру RAM и увеличивает поколение. Если
Direct виден, преобразование цветов и публикация на границе сканирования могут
ещё продолжаться. Состояния: 0 ожидание, 1 загрузка, 2 преобразование, 3 очередь,
4 публикация, 5 готово, 6 отменено. Принятый к публикации кадр завершается за
ограниченное число шагов сканирования; затем обычный рендер учитывает последующие
изменения режима и включения. Suspend и сброс USB-клавиатуры отменяют ожидающую
работу. Физическое поведение светодиодов и DMA требует проверки на устройстве.
Тесты компьютера этого не подтверждают.

## Протокол

Пакет содержит 32 байта. Байт 0 — VIA GET `8` или SET `7`, байт 1 — подкоманда.
Смещения ниже отсчитываются от байта 2. Многобайтные числа — little-endian.
Неиспользуемые байты запроса равны нулю.

| Операция | Подкоманда | Аргументы или ответ |
| --- | --- | --- |
| Возможности GET | `0x45` | `AD`, версия 1, возможности 3, число 82, формат 1 (HSV8), карта 1 (индексы Vial), максимум 160, чтение 7, загрузка 8, таймаут uint16 1000 мс |
| Палитра GET | `0x46` | Запрос: поколение uint32 по 0, начало по 4, число по 5. Ответ: результат по 0, начало по 1, число по 2, флаги по 3, поколение по 4, HSV по 8 |
| Состояние GET | `0x47` | Состояние по 0, число принятых цветов по 1, номер uint16 по 2, поколение uint32 по 4, флаги по 8 |
| Начало SET | `0x43` | Версия 1 по 0, число 82 по 1, номер uint16 по 2, ожидаемое поколение uint32 по 4 |
| Часть SET | `0x44` | Номер uint16 по 0, начало по 2, число по 3, HSV по 4 |
| Commit SET | `0x45` | Номер uint16 по 0 |
| Отмена SET | `0x46` | Номер uint16 по 0 |

Ответ SET заменяет байт аргумента 0 результатом, остальные байты повторяются,
кроме ответа на Часть: в нём каждое принятое значение V ограничено числом 160.
Сначала проверяется диапазон индексов LED, затем ограничивается V. Каждый
компонент HSV занимает один байт пакета.
При сравнении точных повторов цвета сравниваются после нормализации, поэтому
повтор со значением выше 160 принимается, только если после ограничения он
совпадает с уже сохранённым цветом.
Результаты: 0 успех, 1 неверные данные, 2 занято, 3 устаревшее поколение,
4 неполный кадр, 5 другой номер. Флаги: бит 0 — RGB включён, бит 1 — Direct
выбран, бит 2 — suspend. Поколение переполняется как 32-битное число.

Части должны последовательно дополнять кадр. Точный повтор уже принятых цветов
допускается после ограничения яркости. Пропуск, неверный диапазон, другой цвет
при повторе или неполный commit отменяют загрузку с этим номером, сохраняя
активную палитру. Чужой номер не отменяет другую загрузку. Без принятой части
загрузка истекает через 1000 мс. Новое начало заменяет незавершённую загрузку;
при преобразовании или публикации возвращается «занято». Старый fastset отменяет
незавершённую загрузку и увеличивает поколение. Повтор принятого commit не
публикует кадр второй раз. Отмена доступна до принятия commit.

## Резервная копия

Копии ROM и NVM не содержат палитру Direct. Экспорт настроек добавляет отдельный
`direct-ram.json` только для точного образа с `direct_protocol: 1` после
согласования возможностей. Типизированный формат связывает цвета с числом LED,
HSV, картой индексов и пределом яркости. Старые форматы копий не меняются.
Одновременная остановка всех данных RAM и NVM не предполагается.

Восстановление постоянных настроек сохраняет прежнее поведение. Отдельный вызов
`restore_direct_palette` требует явного разрешения записи, точного поддерживаемого
CODE на устройстве, совпадающих возможностей и проверенного файла палитры.
Читается свежее поколение, выполняется commit и проверяется палитра. Этот вызов
не сохраняет цвета в EEPROM и не включает Direct. Старые копии не позволяют
восстановить RAM-палитру.
