# Установка и восстановление

Используйте полный выпуск для проводной AJAZZ AK820 / VS11K28A. Установщик проверяет прошивку в клавиатуре: одного названия модели и USB ID недостаточно. При неподдерживаемой исходной сборке он остановится до стирания. Доказательства и состояние устройства приведены в [статусе](STATUS.md).

## Подготовка пакета

Для выпуска Windows распакуйте архив целиком и запустите `AK820/AK820.exe`. Все распакованные файлы должны оставаться рядом. Для исходного установщика нужен Python 3.10+. Сборка прошивки в Windows использует WSL, но установка готового образа — нет. Офлайн-проверка комплекта:

```sh
./AK820.sh verify
```

```powershell
.\AK820.cmd verify
```

Windows-пакеты из CI содержат резервное копирование, восстановление настроек и поддерживаемое обновление. Используйте полный пакет выбранного выпуска. Отслеживаемый прежний комплект старее; проверенные сборки перечислены в [Статусе](STATUS.md). Офлайн-команда `verify` не загружает HID и не открывает USB.

## Прошивка из выпуска для исходного установщика

Используйте чистую рабочую копию выбранного тега выпуска. Проверьте
`firmware-bundle.zip` по соседнему файлу SHA256 и распакуйте его. Скопируйте
содержимое `firmware-bundle/` в `releases/rc6/`, а его `approved-release.json` —
в `tools/installer/approved-release.json`. До любых команд устройству выполните
`./AK820.sh verify`. Так выбирается прошивка выпуска из CI, а не старый образ
в исходной рабочей копии. Сохраняйте комплект целиком.

## Подготовка исходного установщика в Linux

Нужны Python, его пакеты venv и разработки, GCC и файлы разработки libudev.
В Debian или Ubuntu это, в частности, `build-essential`, `python3-dev`,
`python3-venv` и `libudev-dev`. Затем выполните:

```sh
./AK820.sh setup
./AK820.sh udev --install
```

Setup собирает закреплённый hidapi из исходников с Linux-backend hidraw и
не использует кеш колёс, собранных с другим backend. Команда udev использует
sudo только для установки и применения правила доступа. Сам установщик
запускается от обычного пользователя рабочего стола. Обе команды не сбрасывают
клавиатуру. В ограниченном терминале агента флаг `no_new_privs` может запрещать
sudo даже без пароля; в таком случае команду udev нужно выполнить в обычном
терминале рабочего стола.

## Копия настроек и поддерживаемое обновление

Перед новыми командами прочитайте [Сохранение и восстановление настроек](SETTINGS-BACKUP.md). Поддерживаются только точные проверенные пары образа IHX и кода CODE, указанные там. Для каждой операции нужна корректная OEM-сессия восстановления: для точной реконструкции CODE используются исходные байты, которых нет в репозитории. Храните OEM-сессию и копию настроек отдельно.

Перед восстановлением настроек или обновлением проверьте проводную ревизию VS11K28A. Ни название AK820, ни USB `320F:505B` по отдельности не гарантируют совместимость; V2, Pro и Max не поддерживаются. С неподходящим образом клавиатура может перестать работать.

Поддерживаемые команды:

```sh
./AK820.sh backup --session OEM_DIR --output NEW_DIR
./AK820.sh restore --session OEM_DIR --backup BACKUP_DIR
./AK820.sh update --session OEM_DIR --backup-dir NEW_DIR
```

В Windows используйте те же команды через исходный `AK820.cmd`. Backup читает клавиатуру и создаёт новую личную папку. Restore сначала сохраняет текущее состояние устройства. Update сохраняет настройки, записывает один одобренный образ, затем восстанавливает и проверяет значения. Перед новыми операциями записи появляется окно физической разблокировки; вводить `yes` не нужно. После перезапуска для восстановления потребуется вторая физическая разблокировка. При ошибке работа останавливается без повтора, отката и сброса.

В GUI выберите OEM-сессию и папку для новой копии или готовую копию, затем нажмите «Сохранить настройки», «Восстановить» или «Обновить прошивку». Перед обновлением подготовьте запасную клавиатуру и стабильное питание. По запросу заново удерживайте Esc + левый Ctrl три секунды. На экране будет показано подтверждаемое действие. Если оно выбрано случайно, отмените его до стирания.

## OEM-восстановление

OEM-сессия содержит исходные байты, необходимые для точной реконструкции и проверки поддерживаемой прошивки. Используйте корректную сессию поддерживаемой клавиатуры. Копия настроек не заменяет её. Храните файлы восстановления отдельно и не публикуйте их: ROM и диагностические данные могут содержать личные настройки.

Для восстановления из уже видимого загрузчика выполните исходную команду `recover --session OEM_DIR`. Она не перезапускает работающее приложение и не повторяет неудачное стирание. Если приложение не отвечает, а загрузчик недоступен, остановитесь: программное восстановление в этом состоянии не проверено.

## Прежние сценарии установки

В исходном установщике остаются прежние команды `install`, `install --trial` и `recover --session OEM_DIR`. Их поведение и состояние проверок устройства описаны в [статусе](STATUS.md). Успешная передача файла или checksum не доказывает печать, сохранение настроек после питания или работу после перезапуска.

Офлайн-проверки не разрешают запись в устройство. Каждое обновление требует отдельного подтверждения, свежей резервной копии и проверки точного образа. Alpha — тестовый выпуск; примечания к релизу и статус разделяют исходники, проверки пакета и результаты на устройстве.
