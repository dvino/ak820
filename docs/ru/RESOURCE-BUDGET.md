Суффикс `-short` обозначает проверенные короткие вызовы. Эта настройка
обязательна для трёх новых профилей расширений, `full-mouse-auto-shift-gui`
и `full-auto-shift-dynamic-macro`. Дополнительные строки `full-short` и
`full-mouse-auto-shift-short` показывают второй вариант этих профилей.

Минимальный запас стека равен нулю у Tap Dance и Key Overrides. Расчёт
включает постоянный кадр CRT и все три разных источника IRQ. Любое изменение
образа требует новой проверки. Наблюдавшийся пик в CPU-тесте не заменяет
верхнюю границу. См. [условия расчёта](RUNTIME-STACK.md). Прежние измерения
для `1187d4c` сохранены в своей
[технической матрице](../../audits/rc6/web-firmware-20261024/runtime-all/README.md).

Ёмкость XRAM — 3072 байта отдельно от 512 байт DMA. Окна CODE раздельные:
свободный хвост low нельзя прибавить к main. Профиля со всеми расширениями
и сочетания Mouse Keys + Auto Shift + Dynamic Macros нет.
Новые образы разработки не одобрены для выпуска.

## Опубликованный образ

| Ресурс | опубликованный образ alpha.3 |
| --- | ---: |
| Конец main CODE | `0xc546` |
| Окна CODE | `[0x28a0,0x3000)` и `[0x3027,0xc700)` |
| Свободно в конце окна | 441 main / 16 low |
| XRAM | 2 637 / 3 072 байта |
| Начальный SP / выделение для стека | `0x5d` / 162 байта |
| Слои / макросы / общее хранилище макросов | 6 / 16 / 8 192 байта |

Выделение для стека не является доказанной максимальной глубиной во время
работы. Свободные байты двух окон CODE нельзя объединить. NVM и хранилище
макросов не являются исполняемым CODE.

Опубликованный образ alpha.3 `full` измерен как полная связанная сборка с обоими окнами
CODE и RAM. Основной путь использует 93 байта стека, CRT — 2 байта, три пути
IRQ вместе — 61 байт. Всего используется 156 из 162 байт, остаётся 6 байт.
Числа относятся только к точному квалифицированному образу и не подтверждают
работу физического устройства.

Эти числа стека относятся только к опубликованному образу alpha.3. Они не
применимы к изменённым профилям разработки. Их функции описаны в
[профилях сборки](BUILD-PROFILES.md), а принятые базовые измерения и ограничения
компактных функций — в [техническом отчёте](../../audits/rc6/leader-next-20261024/README.md).

## Обработчики фиксированной сборки Vial

В сборке AK820 на SDCC используются пустые стандартные обработчики записей
клавиш для клавиатуры и пользователя. Их вызовы, копирование аргументов и
неиспользуемый поиск кода клавиши после обработки исключены. На других целях
и в нативных тестовых моделях эти вызовы сохранены. Для собственного обработчика
нужно явно включить путь вызова и заново проверить размер целого образа, стек
и регрессию. Порт на SDCC не поддерживает переопределение через weak-функции.
