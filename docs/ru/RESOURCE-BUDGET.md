# Память и число слоёв

Опубликованный образ `v0.6.0-alpha.3` не изменён. Его идентичность и состояние
установленного устройства приведены в [статусе](STATUS.md). Для текущих исходников
подготовлены девять профилей-пакетов. Точные функции и измерения CODE, XRAM и
стека для каждого образа приводятся в [матрице модулей](MODULE-MATRIX.md);
ресурсы нельзя оценить сложением размера отдельных модулей. Состояние проверок
текущих исходников также описано в [статусе](STATUS.md).

## Опубликованный образ alpha.3

| Ресурс | Опубликованный образ |
| --- | ---: |
| Конец main CODE | `0xc546` |
| Окна CODE | `[0x28a0,0x3000)` и `[0x3027,0xc700)` |
| Свободно в конце окон | 441 main / 16 low |
| XRAM | 2 637 / 3 072 байта |
| Начальный SP / выделение для стека | `0x5d` / 162 байта |
| Слои / макросы / общий буфер макросов | 6 / 16 / 8 192 байта |

Опубликованный образ измерен как полная связанная сборка в обоих окнах CODE и
RAM. Основной путь использует 93 байта стека, CRT — 2 байта, все три пути IRQ
вместе — 61 байт. Всего используется 156 из 162 байт, запас — 6 байт. Эти
показатели относятся только к точному опубликованному образу: они не
квалифицируют изменённую сборку исходников и не подтверждают физическую работу.

Выделенная ёмкость стека не является доказанной границей во время работы.
Свободные байты двух окон CODE нельзя объединить. Ёмкость XRAM — 3 072 байта,
отдельно от 512 фиксированных байт DMA. NVM и макросы не являются исполняемым
CODE.

## Фиксированные обработчики Vial

В сборке AK820 для SDCC используются пустые стандартные обработчики записей
клавиатуры и пользователя. Вызовы, копирование аргументов и неиспользуемый
поиск после обработки исключены. На других целях и в нативных тестах эти пути
сохранены. Добавление собственного обработчика требует явно включить вызовы и
заново проверить размер целого образа, стек и регрессию; порт SDCC не поддерживает
переопределение через weak-функции.
