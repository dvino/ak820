# Проверки

Разделяйте анализ исходников, сборку/целостность, host/CPU и устройство.
Один уровень не заменяет другой. Офлайн-команды из корня:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools/installer -p 'test_*.py' -v
python -B -m unittest discover -s tools -p 'test_build_release_bundle.py' -v
python -B -m unittest discover -s qmk-8051-ak820/tests/ak820_package -p 'test_*.py' -v
```

Общий runner сохраняет команды, коды выхода и hash логов в `host/runs/`.
`--host` включает Linux/WSL C-тесты, `--build-dir` — связанные CPU-наборы.
Команд устройству и прошивки в нём нет.

Host C runner требует GCC/Clang в Linux/WSL. Из `qmk-8051-ak820/` запускайте
`python tests/ak820_usb/run.py`, `python tests/ak820_keymap/run.py`,
`python tests/ak820_caps_word/run.py`, `python tests/ak820_macro_guard/run.py`.
Новые наборы и результаты — в [статусе](STATUS.md). `AK820_SDCC_BIN` указывает
на `bin` закреплённого SDCC.

Проверенные Windows-приложения: `dist/AK820-sdcc46-breathing-20261023/`.
Лог: `host/runs/20261023-sdcc46-windows.json`. Справка CLI, офлайн-проверка,
справка обновления и self-test GUI прошли.
[Независимое ревью](../../audits/rc6/physical-gui-artifact-review.md)
сверило все 26 связанных файлов в каждом приложении. Это проверка упаковки;
отдельные результаты устройства — в [статусе](STATUS.md). Старые папки GUI
и прежний portable ZIP неактуальны.

Связанные CPU-наборы получают новый build directory и `s51`. Точные примеры
команд приведены в [английском оригинале](../TESTING.md). Они исполняют инструкции
с подменённой периферией, не эмулируют кремний VS11K28A и не доказывают все
пути стека. Проверяйте hash образа перед повторным использованием отчёта.

## Автоматические проверки без физических действий

Текущие тесты не требуют нажатий клавиш, вращения ручки, переподключения USB
и ручной разблокировки. Начните с офлайн-команд:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools -p 'test_ak820_device_tests.py' -v
python tools/ak820_device_tests.py
```

Последняя команда только выводит план: обычный запуск не должен открывать HID
или менять настройки. Общий набор включает проверки самого тестового
инструмента. Для готовой Linux-сборки параметры
`--host --build-dir qmk-8051-ak820/.build/local-1` добавляют проверки на ПК
и связанном CPU-коде. Они тоже не отправляют команды устройству.
Для кандидата с проверкой стирания добавьте --iap-fault-profile guarded-erase.
По умолчанию выбран legacy-iap для прежнего образа. Выбор этого параметра
сам по себе не определяет и не подтверждает версию проверяемого образа.

| Что проверяем | Автоматическая проверка | Что она не доказывает |
| --- | --- | --- |
| Клавиши и слои | Чтение всех 83 физических позиций на шести слоях и сравнение с сохранёнными байтами. При отдельном разрешении — смена одной контрольной клавиши на каждом слое и возврат. | Проводку переключателей, время сканирования и печать каждой клавишей |
| Энкодер | Чтение, временная смена и возврат обоих направлений на шести слоях. Один энкодер имеет всего 12 таких назначений. | Сигналы вращения, шаги ручки и физическое нажатие энкодера |
| Макросы | 16 слотов, чтение 8192 байт через протокол и сохранённая длина данных. Запись макросов отмечается SKIP; тесты не запускают разблокировку или сам макрос. | Загрузку макросов с возвратом и запуск физической клавишей |
| RGB | Возможности протокола, 82 записи светодиодов и настройки. При отдельном разрешении — смена и возврат значений в RAM с проверкой, что сохранённые байты не изменились. | Сохранение новых RGB-настроек (SKIP), внешний вид, точность цвета и реакцию на настоящее нажатие |
| Функции ввода | Существующие проверки на ПК/CPU проверяют обработку отчётов, Caps Word, Repeat/Alt Repeat, Grave Escape, Tri Layer и макросы в реализованных случаях. | Физический ввод и электрическую работу USB |
| Ошибки сохранения | Потерю подтверждения, изменение только в кэше, несовпадение сохранённых байтов, порчу соседних данных и неудачный возврат. | Все отказы контроллера и все моменты отключения питания |

Проверки протокола на устройстве предназначены для последующих запусков после
прошивок. Запись настроек требует отдельного согласия и явных параметров;
разрешение на чтение её не разрешает. Перед каждой записью нужен стабильный
снимок без ошибки хранилища. После изменения проверяются ответ, обычное чтение
назначения, точные сохранённые байты и сохранность соседей. Только после этого
можно один раз вернуть исходное значение. При тайм-ауте или несовпадении тест
останавливается и сохраняет данные. В нём нет reset, повторов, запуска
загрузчика и слепого восстановления. Отчёт перечисляет провалы и пропуски,
а не объявляет все функции проверенными.

Для будущей проверки чтением после прошивки нужен Python с `hidapi` и личная
сессия, соответствующая установленному образу. Разрешение релиза и его файлы
проверяются до открытия HID:

```sh
python tools/ak820_device_tests.py --run --release-dir releases/rc6 \
  --session /path/to/personal-session --output host/runs/post-flash-1
```

Выберите новую папку отчёта. Для временного переназначения и проверки RGB
в RAM добавьте **оба** параметра `--allow-settings-write --owner-authorized`,
только после согласия на эти изменения. План, отдельные PASS/FAIL/SKIP,
снимки и журнал запросов остаются в личной папке отчёта. Эти команды никогда
не прошивают клавиатуру и не просят физических действий.

Установленная RC6 прошла холодный запуск, но запись энкодера провалилась на
`target_write`. Этот случай должен воспроизводиться в офлайн-тестах. В текущей
работе новые команды и прошивки на клавиатуре с этой ошибкой не запускаются.

## Приёмка устройства

Только после подтверждения владельца и подготовки запасного ввода:

1. Проверить main loop, обычный текст, модификаторы, мультимедиа.
2. Каждую клавишу, нажатие и оба направления энкодера, отпускание сочетаний.
3. Сохранить remap, слои, энкодер, макрос и RGB; проверить после рестарта.
4. Дважды отключить питание и подключить. Постоянная прошивка должна стартовать
   с настройками; trial — следовать своему пути в загрузчик.
5. Проверить LED: темнота в покое, соответствие клавише, сочетания, повтор,
   затухание, яркость и смена режимов. Численная модель внешний вид не подтверждает.
6. Проверить Vial unlock/lock и Bootloader recovery со своей копией.

Записать точный SHA256, вариант устройства, ОС, действия и результат.
Провал шага остаётся провалом даже при успешном checksum.
