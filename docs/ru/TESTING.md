# Проверки

Разделяйте анализ исходников, сборку и целостность, исполнение на ПК/CPU-модели
и физическую работу клавиатуры. Один уровень не заменяет другой.

## Текущий офлайн-результат

Сохранённый [отчёт](../../audits/rc6/roadmap-qualification-20261023/final/report.json)
содержит 23 успешных набора, 247 unit-тестов без пропусков и неизменные хеши
IHX/MAP на всём протяжении прогона. Прошли восемь наборов C-тестов на ПК и
шесть наборов CPU-модели; ещё один проверяет документы. Образ — кандидат для
разработки из [Статуса](STATUS.md), а не новый одобренный пакет обновления.

| Unit-набор | Прошло тестов |
| --- | ---: |
| Установщик и логика GUI | 111 |
| Сборка комплекта | 12 |
| Рецепт Windows-пакета | 12 |
| Общий запуск тестов | 10 |
| Программа проверки устройства | 19 |

Тесты настроек используют синтетические ответы протокола и временные файлы.
Частные ROM-копии не читаются, клавиатура не открывается. Работа на устройстве
остаётся привязана к точному выпуску из [Резервных копий настроек](SETTINGS-BACKUP.md).
Офлайн-`verify` проходит без HID. [Ревью исходников и пакета](../../releases/rc6/reviews/independent-review.md)
связывает выпуск и host-файлы; оно не относится к новому кандидату или EXE.

[Манифест доказательств](../../audits/rc6/roadmap-qualification-20261023/manifest.json)
сохраняет начальную неудачную попытку и итоговый прогон. В итоговом прогоне
LeakSanitizer отключён: сведения о процессах недоступны в песочнице. Проверки
адресов и неопределённого поведения в использующих их C-тестах остаются;
утечки памяти не проверялись. Сборка Windows EXE, приёмка Tk, запись настроек
на устройстве и физическая сохранность остаются непроверенными. Пропуски
live-программы ниже не относятся к результату unit-тестов без пропусков.

## Запуск офлайн-наборов

Из корня репозитория:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools/installer -p 'test_*.py' -v
python -B -m unittest discover -s qmk-8051-ak820/tests/ak820_inventory -p 'test_*.py' -v
```

Общая программа сохраняет команды, коды выхода, хеши журналов и инструментов,
число тестов и пропусков в `host/runs/`. Она выбирает локальный SDCC 4.6.0 или
установку из `--toolchain`; `AK820_SDCC_BIN` также поддерживается. Выбранные
компилятор и симулятор передаются дочерним наборам. Инвентаризация проверяется
по умолчанию, `--host` добавляет в том числе новые C-тесты, а `--build-dir` —
новую проверку слинкованной функции вместе с остальными CPU-наборами.
Команд устройству и тестов прошивки через USB нет.

С установленными инструментами и готовой свежей сборкой:

```sh
python tools/test_keyboard.py --host --require-toolchain \
  --toolchain toolchains/sdcc-4.6.0 \
  --build-dir qmk-8051-ak820/.build/local-1 \
  --iap-fault-profile guarded-erase --output host/runs/qualification.json
```

`--require-toolchain` требует инструменты и считает любой пропуск unit-теста
провалом общей проверки. Без него обычный запуск работает и без компилятора,
сохраняя сведения о пропусках. Ошибка запуска дочернего процесса — провал.
Хеши IHX/MAP до, после каждого набора и в конце выявляют временную подмену,
даже если итоговые файлы затем вернули.

C-тестам нужны GCC/Clang в Linux/WSL. Отчёт записывает заданное окружение
санитайзеров. `ASAN_OPTIONS=detect_leaks=0` нужен только когда песочница мешает
LeakSanitizer читать сведения о процессах; это ограничение следует записать.
В Bash поставьте это присваивание перед общей командой. Именно так выполнен
сохранённый итоговый прогон.

Команды Windows-пакета приведены в [Сборке](BUILD.md). Двенадцать тестов рецепта
подменяют собранные файлы и результаты запуска. Для EXE и создания настоящего
интерфейса Tk нужен запуск в Windows; видимые диалоги требуют отдельной
интерактивной проверки.

## Повторное использование сохранённых сборок

Архив исходников содержит контрольные отчёты, все указанные в них артефакты и
перемещённые листинги. Для инвентаризации кандидата временные каталоги проб
не нужны. Из корня репозитория:

```sh
python qmk-8051-ak820/util/ak820_linked_inventory.py \
  --root audits/rc6/bounded-evidence-20261023/pointer \
  --report audits/rc6/bounded-evidence-20261023/pointer/.build/bounded-probe/build-report.json \
  --output /tmp/ak820-pointer-inventory.json
python qmk-8051-ak820/tests/ak820_bounded/emitted.py \
  --build-dir audits/rc6/bounded-evidence-20261023/pointer/.build/bounded-probe \
  --s51 toolchains/sdcc-4.6.0/bin/s51 \
  --output-dir host/runs/linked-header-1
```

Второй команде нужен закреплённый симулятор из [Сборки](BUILD.md). Используйте
новую папку результатов. Исходные отчёты сохраняют прежние пути как сведения
о происхождении; манифесты указывают переносимые копии. Инвентаризация проверяет
записанные артефакты и байты инструкций, но явно показывает частичное покрытие.
[Отчёт](../../audits/rc6/linked-inventory-20261023.md) описывает ограничения и
команду для контрольной сборки.

Новый C-тест извлекает производственные функции и проверяет 264 448 заголовков
журнала и 65 025 пар задержки. На слинкованном коде проверяются 2304 изменения
заголовка и расход стека этой функции. Правильное проигрывание макросов
проверяется на всех 16 слотах. Произвольно обрезанные операнды, переданные
напрямую в проигрыватель, не входят в правило полного опубликованного потока
этого теста. Унаследованная проблема и отдельная проверка записи хранилища
описаны в [отчёте о пробах](../../audits/rc6/bounded-optimization-20261023.md).

Другие CPU-наборы принимают свежую сборку и закреплённый симулятор. Из
`qmk-8051-ak820/`, например:

```sh
python tests/ak820_features/run.py --build-dir .build/local-1 \
  --s51 ../toolchains/sdcc-4.6.0/bin/s51 --output-dir .build/local-1-features
python tests/ak820_irq/run.py --build-dir .build/local-1 \
  --s51 ../toolchains/sdcc-4.6.0/bin/s51 \
  --stock-rom /path/to/private-oem-references/stock-full.bin \
  --output-dir .build/local-1-irq --main-sample-bytes 80
```

IRQ-примеру нужен частный OEM ROM, которого нет в архиве; в итоговый общий
прогон он не входил. Частные ROM нельзя добавлять в выпуск. CPU-тесты
подменяют периферийные операции, не эмулируют USB/flash-кремний VS11K28A
и не доказывают безопасность всех путей стека и прерываний.

## Автоматические проверки без физических действий

Текущие тесты не требуют нажатий клавиш, вращения ручки, переподключения USB
и ручной разблокировки. Начните с офлайн-команд:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools -p 'test_ak820_device_tests.py' -v
python tools/ak820_device_tests.py
```

Последняя команда только выводит план: обычный запуск не должен открывать HID
или менять настройки. Общий набор включает проверки самого тестового
инструмента. Для готовой Linux-сборки параметры
`--host --build-dir qmk-8051-ak820/.build/local-1` добавляют проверки на ПК
и связанном CPU-коде. Они тоже не отправляют команды устройству.
Для кандидата с проверкой стирания добавьте --iap-fault-profile guarded-erase.
По умолчанию выбран legacy-iap для прежнего образа. Выбор этого параметра
сам по себе не определяет и не подтверждает версию проверяемого образа.

| Что проверяем | Автоматическая проверка | Что она не доказывает |
| --- | --- | --- |
| Клавиши и слои | Чтение всех 83 физических позиций на шести слоях и сравнение с сохранёнными байтами. При отдельном разрешении — смена одной контрольной клавиши на каждом слое и возврат. | Проводку переключателей, время сканирования и печать каждой клавишей |
| Энкодер | Чтение, временная смена и возврат обоих направлений на шести слоях. Один энкодер имеет всего 12 таких назначений. | Сигналы вращения, шаги ручки и физическое нажатие энкодера |
| Макросы | 16 слотов, чтение 8192 байт через протокол и сохранённая длина данных. Запись макросов отмечается SKIP; тесты не запускают разблокировку или сам макрос. | Загрузку макросов с возвратом и запуск физической клавишей |
| RGB | Возможности протокола, 82 записи светодиодов и настройки. При отдельном разрешении — смена и возврат значений в RAM с проверкой, что сохранённые байты не изменились. | Сохранение новых RGB-настроек (SKIP), внешний вид, точность цвета и реакцию на настоящее нажатие |
| Функции ввода | Существующие проверки на ПК/CPU проверяют обработку отчётов, Caps Word, Repeat/Alt Repeat, Grave Escape, Tri Layer и макросы в реализованных случаях. | Физический ввод и электрическую работу USB |
| Ошибки сохранения | Потерю подтверждения, изменение только в кэше, несовпадение сохранённых байтов, порчу соседних данных и неудачный возврат. | Все отказы контроллера и все моменты отключения питания |

Проверки протокола на устройстве предназначены для последующих запусков после
прошивок. Запись настроек требует отдельного согласия и явных параметров;
разрешение на чтение её не разрешает. Перед каждой записью нужен стабильный
снимок без ошибки хранилища. После изменения проверяются ответ, обычное чтение
назначения, точные сохранённые байты и сохранность соседей. Только после этого
можно один раз вернуть исходное значение. При тайм-ауте или несовпадении тест
останавливается и сохраняет данные. В нём нет reset, повторов, запуска
загрузчика и слепого восстановления. Отчёт перечисляет провалы и пропуски,
а не объявляет все функции проверенными.

Для будущей проверки чтением после прошивки нужен Python с `hidapi` и личная
сессия, соответствующая установленному образу. Разрешение релиза и его файлы
проверяются до открытия HID:

```sh
python tools/ak820_device_tests.py --run --release-dir releases/rc6 \
  --session /path/to/personal-session --output host/runs/post-flash-1
```

Выберите новую папку отчёта. Для временного переназначения и проверки RGB
в RAM добавьте **оба** параметра `--allow-settings-write --owner-authorized`,
только после согласия на эти изменения. План, отдельные PASS/FAIL/SKIP,
снимки и журнал запросов остаются в личной папке отчёта. Эти команды никогда
не прошивают клавиатуру и не просят физических действий.

Прежний кандидат RC6 на SDCC 4.4 прошёл холодный запуск, но запись энкодера
провалилась на `target_write`. Это исторический случай, сохранённый в офлайн-
тестах. Более поздние результаты SDCC 4.6 приведены в [статусе](STATUS.md);
они не заменяют новую проверку настроек и сохранения после потери питания.

## Приёмка устройства

Только после подтверждения владельца и подготовки запасного ввода:

1. Проверить main loop, обычный текст, модификаторы, мультимедиа.
2. Каждую клавишу, нажатие и оба направления энкодера, отпускание сочетаний.
3. Сохранить remap, слои, энкодер, макрос и RGB; проверить после рестарта.
4. Дважды отключить питание и подключить. Постоянная прошивка должна стартовать
   с настройками; trial — следовать своему пути в загрузчик.
5. Проверить LED: темнота в покое, соответствие клавише, сочетания, повтор,
   затухание, яркость и смена режимов. Численная модель внешний вид не подтверждает.
6. Проверить Vial unlock/lock и Bootloader recovery со своей копией.

Записать точный SHA256, вариант устройства, ОС, действия и результат.
Провал шага остаётся провалом даже при успешном checksum.

## Непрерывная интеграция

Проверки push и pull request, сборка Windows и выпуски по тегам описаны в
[CI и выпусках](CI.md). Workflow также запускает модели прерывания записи
NVM и макросов. Операции с устройством не выполняются.
