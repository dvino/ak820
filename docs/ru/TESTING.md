# Проверки

Офлайн-набор проверяет выбранные исходники и связанный образ прошивки. Он не
подтверждает работу физической клавиатуры. Десять профилей beta.2 прошли
офлайн-проверки; результаты и ограничения приведены в [статусе](STATUS.md).

## Офлайн-регрессия

Из корня репозитория запустите общие офлайн-проверки:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools/installer -p 'test_*.py' -v
python -B -m unittest discover -s qmk-8051-ak820/tests/ak820_inventory -p 'test_*.py' -v
```

Для сборки и квалификации релизного профиля сначала подготовьте свежий
проверенный сертификат контекста исходников и IRQ для текущих исходников.
Для каждого профиля используйте новый каталог сборки:

```sh
python tools/configure_firmware.py build --profile main \
  --parameter-spills-context /path/to/current-source-irq-context.json \
  --build-dir qmk-8051-ak820/.build/beta2-main \
  --toolchain toolchains/sdcc-4.6.0
```

Сборка использует релизные преобразования, требующие сертификат контекста,
затем квалифицирует точный связанный образ. Сначала проверяются память и
границы стека для основного пути, запуска и всех включённых прерываний.
После этого запускаются полные базовые и профильные офлайн-наборы. Чтобы
повторно квалифицировать уже связанный образ:

```sh
python tools/configure_firmware.py qualify \
  --build-dir qmk-8051-ak820/.build/beta2-main \
  --toolchain toolchains/sdcc-4.6.0
```

Повторите сборку для каждого нужного профиля из списка
`python tools/configure_firmware.py list`. Профиль по умолчанию — `main`.
Проверки функций запускаются только если выбранный образ включает нужный
модуль; Grave Escape не входит в `main`. В отчёте квалификации указаны
запущенные и пропущенные наборы. В beta.2 десять исходных профилей, но их
описания и результаты предыдущих профилей не квалифицируют новый образ.
Для каждого из десяти образов beta.2 прошли 28 базовых наборов, 331 юнит-тест
без пропусков и 32–37 дополнительных наборов. [Отчёт проверки](https://github.com/dvino/ak820/blob/v0.6.0-beta.2/audits/rc6/beta2-release-20261025/qualification-final.json)
связывает результаты с точными образами. Каждая новая сборка требует собственной проверки.

Стандартный анализ IRQ использует общедоступный набор инструкций OEM и не
требует доступа к закрытой ROM. CPU-фикстуры моделируют работу периферии, но не USB и
flash-контроллер VS11K28A. Результаты host и CPU не подтверждают работу
физического устройства или сохранность после полного отключения питания.

Автоматические проверки не требуют нажимать клавиши, вращать энкодер,
переподключать кабель или вручную разблокировать Vial и не записывают данные
в клавиатуру. Проверки живого протокола выполняются отдельно; по умолчанию
они доступны только для чтения. Для записи настроек нужны явные параметры
запуска и разрешение. Тайм-аут, ошибка хранилища и неверное чтение останавливают
проверку. Не повторяйте действие вслепую, не сбрасывайте устройство и не
восстанавливайте настройки.

## Проверки устройства и ограничения

Live runner читает назначения клавиш и энкодера, слоты макросов, настройки RGB
и доступные getters. Чтение не подтверждает работу физических клавиш, скорость
сканирования, сигналы энкодера, запуск макросов, вид освещения или надёжность
хранения. Для проверки нужны одобренный пакет и сессия, относящиеся к одному
точному образу. Для разрешённой проверки только чтением укажите распакованный
одобренный пакет выбранного образа и новый закрытый каталог результатов:

```sh
python tools/ak820_device_tests.py --run \
  --release-dir /path/to/extracted-approved-selected-bundle \
  --approval /path/to/exact-approved-release.json \
  --session /path/to/permanent-session-for-the-same-image \
  --output host/runs/post-flash-1
```

Пакет, файл одобрения и сессия должны указывать на один образ. Не используйте
одобрение для другого образа или старый каталог `releases/rc6`. Команда не
прошивает клавиатуру и не требует физических действий.

## Физическая приёмка

Перед прошивкой требуется отдельное явное подтверждение. Проверьте ввод,
модификаторы, медиа-клавиши, физические клавиши, нажатие энкодера и оба
направления, время Combo, подсветку, обновление и настройки после перезапуска
и полного отключения питания. Запишите хеш образа, вариант устройства, шаги
и результаты. Проверки host и CPU не заменяют эти проверки.
