# Проверки

Опубликованный образ `v0.6.0-alpha.3` прошёл наборы CI, приведённые в отчёте;
есть ограниченные результаты проверки устройства. Точные данные о сборке и
устройстве приведены в [статусе](STATUS.md). Модели host и выполнение linked
CPU не доказывают работу физической клавиатуры. Подробные проверки отдельных
функций и работа после полного отключения питания ещё не проверены.

## Офлайн-набор регрессии

Из корня репозитория запустите офлайн-набор и связанные unit-тесты:

```sh
python tools/test_keyboard.py
python -B -m unittest discover -s tools/installer -p 'test_*.py' -v
python -B -m unittest discover -s qmk-8051-ak820/tests/ak820_inventory -p 'test_*.py' -v
```

Общий запуск записывает команды, коды завершения, хеши и пропуски. Для полной
квалификации уже связанного образа с закреплёнными инструментами:

```sh
python tools/configure_firmware.py qualify \
  --build-dir qmk-8051-ak820/.build/local-1 \
  --toolchain toolchains/sdcc-4.6.0
```

В проверку входят обработка ввода и отчётов, Caps Word, Repeat и Alt Repeat,
Grave Escape, Tri Layer, tap-hold, Combo, макросы, RGB и NVM — в пределах
покрытия host- и CPU-фикстур. Покрытие зависит от запуска и сборки; смотрите
сформированный отчёт. Автономная проверка IRQ использует общедоступный набор
инструкций OEM и не требует частной ROM. CPU-фикстуры моделируют работу периферии, но не эмулируют
USB или flash-контроллер VS11K28A. Измеренный максимум стека не является общей
верхней границей.

Для девяти готовых пакетов используйте сборщик конечного каталога профилей.
Список из девяти строк матрицы CI показывает параметр `--list`; затем соберите
и квалифицируйте все точные образы:

```sh
python tools/build_profile_catalog.py --list
python tools/build_profile_catalog.py \
  --build-root qmk-8051-ak820/.build/catalog \
  --output .build/profile-catalog
```

Путь вывода задаёт новый каталог; рядом создаются ZIP и файл SHA256.
Сборщик проверяет границы стека и прерываний точного образа до регрессионных
проверок. Параметр `--resume` повторно квалифицирует уже связанные образы и
запускает проверки заново; он не пропускает этапы. Каталог содержит офлайн-
доказательства, но не разрешает прошивку устройства. Текущая квалификация и
состояние выпуска приведены в [статусе](STATUS.md). Отдельные сборки пакетов и
старые профили CLI описаны в [профилях сборки](BUILD-PROFILES.md).

Автоматический набор не требует нажимать клавиши, вращать энкодер, отключать
кабель или вручную разблокировать Vial. Он не записывает данные в клавиатуру.
Проверки живого протокола выполняются отдельно. План запуска по умолчанию
доступен только для чтения; для записи настроек нужны явные параметры запуска
и разрешение. Тайм-ауты, ошибки хранилища и неверное чтение считаются ошибкой
и останавливают запуск. Нельзя вслепую повторять действие, перезапускать
устройство, восстанавливать данные или входить в загрузчик.

## Проверки устройства и ограничения

Live runner может читать 83 назначения матрицы на шести слоях, назначения
энкодера в обоих направлениях на шести слоях, 16 слотов макросов и окно
8192 байта, RGB-настройки и доступные getters. Чтение не проверяет физические
клавиши, время сканирования, сигналы энкодера, выполнение макросов, вид света
или долговечность хранения. Для опубликованного образа проверены установка и
резервное копирование с восстановлением настроек; точный объём указан в
[статусе](STATUS.md). Отдельные физические проверки функций и сохранность после
потери питания ещё не проверены.

Для будущей разрешённой диагностики только на чтение используйте личную сессию
и новый каталог результатов:

```sh
python tools/ak820_device_tests.py --run \
  --release-dir /path/to/extracted-alpha3-firmware-bundle \
  --approval /path/to/exact-alpha3-approved-release.json \
  --session /path/to/permanent-session-for-the-same-alpha3-image \
  --output host/runs/post-flash-1
```

Каталог выпуска, файл одобрения и сессия должны указывать на точный образ для диагностики. Нужна новая сессия установки/восстановления; одной OEM-копии или копии настроек недостаточно. Не используйте старый каталог `releases/rc6` с файлом одобрения другого образа. План и результаты остаются в закрытом каталоге. Проверки с записью требуют явных параметров запуска и разрешения. Тесты не прошивают клавиатуру и не требуют физических действий.

## Физическая приёмка

Перед прошивкой требуется явное подтверждение. Проверьте ввод текста,
модификаторы, медиа-клавиши, каждую клавишу, нажатие энкодера и оба направления,
время Combo, вид света, разблокировку/обновление и настройки после перезапуска
и полного отключения питания. Запишите хэш точного образа, вариант устройства,
действия и результат. Host- и CPU-проверки не заменяют эти проверки.
