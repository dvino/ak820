# Сжатие полной прошивки

Цель — один образ `maximal` со всеми 14 дополнительными модулями и базовыми
функциями. Состав функций и объёмы хранилищ закреплены в
[плане](../MAXIMUM-FUNCTIONALITY-PLAN.md).

## Текущий образ: 28

`.build/resume28-keymap-firewall` занимает **44 638 байт CODE**. Основное окно
переполнено на **4 285 байт**. Это диагностический образ; устанавливать его
нельзя. Физические окна CODE остаются `[0x28a0,0x3000)` и `[0x3027,0xc700)`.
Резервы загрузчика, NVM, макросов и LED DMA сохранены.

| Измерение | Значение |
| --- | ---: |
| Занятый CODE: нижнее / основное окно | 1 741 / 42 897 байт |
| Последний адрес основного окна | `0xd7bc` |
| Обычная XRAM + буфер записи | 2 943 + 64 = 3 007 / 3 072 байт |
| Ёмкость стека | 167 байт |
| Границы main / USB / timer / LED | 103 / 5 / 2 / 2 байта |
| Неразрешённые пути от этих корней | 0 |
| Условная общая граница / запас | 165 / 2 байта |

Расчёт: `103 + 2 + 3 × 17 + 5 + 2 + 2`. Учтены вход CRT в main и все разные
источники прерываний. Полный контракт банков, обёрток OEM, маршрутизации и
запрета повторного входа ещё не закрыт. Этот расчёт не подтверждает готовность
прошивки.

SHA256 IHX: `87467a0fdae46f4e222de6968b6e1cb48d155bfca77f81363acb947a37e17d1b`.
[Машинный отчёт](../maximal-current.json) и [проверки прохода 28](../../audits/maximal-pass28-20261025/README.md)
связывают размеры с исходниками, инструментами, образами и ограниченными проверками.

## Изменение и проверки

Обработчик записи буфера раскладки напрямую перебирает затронутые пары байтов
при проверке запрещённого boot-кода в заблокированном состоянии, включая
неполные пары. Порядок чтений, отказ до записи, принятые данные и форматы
хранения сохранены. Образ maximal экономит **61 байт связанного CODE** против
сохранённого прохода 27 без изменения XRAM и ёмкости стека. Отличающийся
исторический `dynamic_keymap.c` проверяется по полному записанному коммиту Git,
остальные входные данные — на месте. [Материалы прохода 27](../../audits/maximal-pass27-20261025/README.md)
не изменены.

Сравнение на ПК проходит 6 849 504 случая с ASan/UBSan и обнаруживает три
намеренно ошибочные версии и изменение алиаса. Модель ошибки чтения возвращает
`0xff` и устанавливает сохраняемый флаг ошибки; сбои записи и устойчивое
хранение она не моделирует. Точный связанный обработчик проходит 600 случаев
CPU-модели: неполные граничные пары, запись совпадающих данных, состояния
блокировки и кэша, 88 ранних отказов. Все 44 638 занятых байт CODE сохранены.
Вызовы используют одну страницу кэша; новые ошибки чтения, переходы между
грязными страницами, flash и IRQ этой проверкой не покрыты.

Проверки стека, CRT и конечная проверка чтения для точного образа проходят.
Сертификаты контекста прохода 27 и их ревью сохранены побайтно. Защищённый ASM
компилятора, инструменты, карта памяти и происхождение перепроверены; привязки
после связывания проверены заново для образов 28. Новые сертификаты контекста
не создавались. Другие ограниченные CPU-проверки проходят 629 случаев RGB,
576 Combo GET, 48 обновлений только в кэше, 15 порядков разных IRQ и 256
селекторов LED. Все 4 285 занятых байт от `0xc700` сохранены в 20 сеансах.
CRT выполняется только до входа в main; основной цикл и инициализация
NVM/настроек не покрыты.

Контрольный `work` из текущих исходников занимает 37 392 байта CODE и 2 554
байта физической XRAM: на 78 байт CODE меньше сохранённого work прохода 27.
Последний адрес — `0xbb6e`, свободный хвост основного окна — 2 961 байт.
Границы main/USB/timer/LED — 98/5/2/2; условный итог — 160 из 171 байта стека,
запас 11. Ограниченная CPU-проверка IRQ сохраняет весь занятый CODE в 17
сеансах. Контрольный образ не заменяет выпущенную прошивку.

Оба ассемблерных ядра NVM и прежние сокращения компилятора включены; IRAM
overlay выключен. Открыты сокращение CODE, полный контракт OEM startup/IRQ и
банков, непрозрачный writer, полная регрессия и физическая проверка. Цель полной
прошивки ещё не достигнута. Действия с устройством, установщиками, упаковкой
и выпусками не выполнялись.
