# Сжатие всей прошивки

Цель — сохранить все 14 дополнительных модулей вместе с общей основой. В
полной сборке остаются индикатор OS, шесть слоёв, 16 макросов Vial с буфером
8192 байта, восемь двухклавишных Combo, восемь Tap Dance, восемь Key Overrides,
оба направления энкодера и NKRO. Фиксированные окна CODE: `[0x28a0, 0x3000)`
и `[0x3027, 0xc700)`. Общий предел XRAM — 3072 байта.
[План](../MAXIMUM-FUNCTIONALITY-PLAN.md) описывает работу по уменьшению
размера.

## Текущий образ 26b

Образ `.build/resume26b-state-bytes` содержит все 14 модулей. Он занимает 44
747 байт CODE: 1 741 байт в нижнем окне и 43 006 в основном. Верхний адрес
основного кода — `0xd829`; превышение окна — 4 394 байта. Обычная XRAM
занимает 2 943 байта, резерв flash — 64 байта, всего 3 007 из 3 072. Стек:
доступно 167 байт.

SHA256 IHX:
`47400365dfe8e7e56fd46a548938ca8c9024467ca13120f506cb7213e9f7ef10`.
Машинные данные находятся в [текущем отчёте](../maximal-current.json); файлы
замеров, ревью и сводка собраны в [отчёте продолжения](../../audits/maximal-continuation-20261025/README.md).

Точные корни приложения имеют границы 103/5/2/2 байта для основного пути, USB,
таймера и LED; неизвестных переходов нет. Анализ запуска учитывает два байта
CRT. Условная суммарная оценка — 165 байт: `3 × 17 + 5 + 2 + 2 + 103 + 2`. При
доступных 167 байтах остаётся два байта запаса. Расчёт условный: завершённая
проверка OEM запуска, маршрутизации и вложения прерываний ещё отсутствует.
Поэтому он не подтверждает готовность всей прошивки.

IRAM overlay выключен; чтение и обновление NVM включены; частное сокращение
spill-последовательностей версии 2 включено. Контрольная сборка на исходниках
образа 22 с выключенной опцией ассемблерного чтения сохранила прежний C-обработчик
блочного чтения и дала 45 499 байт CODE и 2 980 байт XRAM. С включённой опцией
чтения образ 22 дал 45 461 байт CODE и 2 976 байт XRAM: разница — минус 38
байт CODE и четыре байта XRAM. Базовый образ 22
воспроизведён побайтно: IHX
`576fd31f4ccbe85f722cf0837c688aee69c5a517694f5d8828bdc0a8d3067fe8`, 45 461
байт CODE, 2 976 байт XRAM и 156 байт доступного стека.

Промежуточные образы показывают общий результат изменений:

| Этап | CODE, байт | XRAM, байт | Стек, байт |
| --- | ---: | ---: | ---: |
| База 22 | 45 461 | 2 976 | 156 |
| Проверка NVM update, образ 24 | 45 173 | 2 961 | 167 |
| DPTR, образ 25 | 45 056 | 2 961 | 167 |
| Массив tap-hold и One Shot, образ 26b | 44 747 | 3 007 | 167 |

Итого относительно базы: минус 714 байт CODE, плюс 31 байт XRAM и 11 байт
ёмкости стека. Образ 26b всё ещё превышает главное окно CODE на 4 394 байта.

## Что изменено и проверено

- В Combo обработчик GET сразу записывает ответ в XDATA. Обработчик SET
  не менялся.
- Вспомогательная функция LED ограничена фиксированным буфером из 32 байт.
  Проверки перебирают сетку индексов, счётчиков и длин, а также крайние
  значения байтов; все возможные 32-байтовые пакеты не перебираются.
- Ассемблерное обновление NVM по умолчанию выключено. При включении оно
  останавливается на первом отличии и передаёт исходному C-записывателю
  исходные три байта generic-адреса (16-битный адрес и тег) и 16-битную длину.
  При равном или пустом запросе запись не вызывается. Исходный указатель
  источника также сохраняется. В цикле байт NVM читается раньше байта
  источника. Сравнение сохраняет R0/R1; обычная C-функция записи вправе
  менять их.
- Проход DPTR удаляет лишнее восстановление регистра непосредственно перед
  полной перезаписью. Допускаются только простой символ C или фиксированная
  16-битная константа. Выражения с текущим адресом инструкции исключены
  после исправления проверки.
- Массив состояния tap-hold и One Shot размером 82 байта заменён массивом
  из 130 байт. Все пять независимых флагов сохранены; запись ограничена
  маской 31. В полной сборке это увеличивает RAM на 46 байт и уменьшает
  CODE на 309 байт.
- Проверка существующего скалярного хука чтения NVM анализирует 45 достижимых
  инструкций, оценивает два байта стека и отклоняет все семь проверенных
  изменений тела. Новый обработчик чтения этим не добавлялся.

Проверки компонентов и модели CPU прошли в своих границах:

- Combo: 32 768 × 2 сравнений.
- LED: тестовая сетка индексов, счётчиков, длин и крайних значений с ASan/UBSan.
- Обновление NVM: 3 169 парных тестов с mock-функциями s51.
- DPTR: 15 тестов условий преобразования и 1 024 пары на CPU.
- tap-hold/One Shot state: 151 444 930 сравнений и 1 164 960 записей;
  дополнительно прошли 156 тестов QMK и 13 отрицательных проверок.

Результаты моделей отдельных компонентов приведены выше. В CPU-модели точного
образа проверены RGB (629 случаев), Combo (576) и NVM (48). Также проверены
15 упорядоченных вложений IRQ, все 256 значений селектора LED и сохранность
области CODE от `0xc700` и выше в 20 сессиях. Эти проверки не являются
выполнением прошивки на устройстве.

## Контроль профиля work

На текущих исходниках `work` занимает 37 545 байт CODE и 2 554 байта XRAM.
Верхний адрес — `0xbc07`, в конце основного окна остаётся 2 808 байт.
Свежая условная оценка стека — 160 из 171 байта. Пройдены 15 порядков IRQ
и все 256 селекторов LED; все 37 545 байт кода сохранились в 17 сессиях.
Это отдельная контрольная сборка. Она не заменяет выпущенный образ work
и не подтверждает готовность maximal.

## Ограничения

Полные регрессии для собранной конфигурации не выполнялись: CODE выходит за
пределы основного окна, а подтверждённого полного OEM-контракта запуска,
маршрутизации прерываний и запрета повторного входа нет. Остаются также
проверки банков регистров приложения и контракта непрозрачного записывателя.
Условный запас стека в два байта не закрывает эти пробелы.

Результаты не подтверждают физическое поведение клавиатуры, работу при
реальных прерываниях, задержки устройства или устойчивость записи flash.
Записей на устройство, сбросов и переходов в загрузчик не было.
Установщики, выпуски и установленная прошивка не менялись.

Отложены два варианта. Вынесение повторяющегося кода с прямым доступом DATA может сэкономить
номинально 131–175 байт, но требует нового доказательства. Таблица Tap Dance
сэкономила бы 66 байт объектного CODE ценой 64 байт RAM; её ценность невелика.
Оба варианта требуют отдельной проверки точного образа.
