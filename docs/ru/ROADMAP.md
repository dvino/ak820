# Планы

В исходниках есть 24 именованных профиля разработки. Для компактных Tap Dance,
Key Overrides и QMK Settings предусмотрены отдельные профили: каждый добавляет
к `full` только один модуль. Профиля со всеми тремя модулями нет. Эти профили
исходников не одобрены для выпуска. Опубликованная и установленная alpha.3
остаётся без изменений. Список профилей приведён в [руководстве по сборке](BUILD-PROFILES.md),
точные ограничения — в руководствах модулей.

## Следующий этап

Следующий этап продукта — контракт настольного конфигуратора и каталог
возможностей. Клиент должен получать доступные элементы управления из каталога
точного связанного образа, различать зарезервированное место и включённые функции
и показывать только поддерживаемые профилем команды. Резервное копирование и
восстановление должны использовать типизированный контракт хранения модулей и
отклонять настройки, которые целевой образ не может представить. См.
[требования конфигуратора](../../web/docs/REQUIREMENTS.md),
[план реализации](../../web/docs/PLAN.md) и
[каталог разработки](../DEVELOPMENT-CATALOG.md).

## Будущие функции

Текущие модули имеют узкие контракты. Tap Dance поддерживает восемь записей,
четыре базовых или модифицированных базовых вывода на запись, одно ожидающее
решение и не более двух нажатий в жесте; уже разрешённые удержания могут
перекрываться. Key Overrides поддерживает восемь строк и одновременно захватывает
один физический триггер. QMK Settings предоставляет QSIDs 1, 2, 7, 18 и 19;
QSID 4 зарезервирован для будущего профиля, который объединит модуль с Auto Shift.
Запись настроек — типизированная версия на 24 байта с CRC и поддержкой резервной
копии и миграции. Ограничения действий и поведения описаны в руководствах модулей.

Другие действия Magic остаются будущей работой. Текущие команды GUI и перестановки
модификаторов временные. Варианты Caps и постоянные настройки Magic не входят в
текущий контракт. Для расширения нужно определить поведение для пользователя,
правила хранения и миграции (если они нужны), а также проверить ресурсы и runtime
точного образа до рассмотрения выпуска.

## Хранение и совместимость

Схема `0x082003` используется только тремя новыми профилями модулей. Существующие
форматы `0x082002` и настройки выпуска не меняются. Сохранены шесть слоёв,
16 макросов с буфером 8192 байта, восемь Combo и их фиксированный адрес `0x658`.
Новые записи модулей используют зарезервированное пространство, описанное в
разделе [Хранение модулей](MODULE-STORAGE.md). Не включайте upstream-хранилище
QMK Settings: оно сдвигает фиксированную раскладку Combo.

Новые сочетания профилей должны сохранять существующую ёмкость и поведение
хранилища. Стоимость функций зависит от полного связанного образа, поэтому для
каждого профиля отдельно измеряются CODE, RAM и стек. Данные runtime и регрессии
приведены в [статусе](STATUS.md); профиль исходников не подтверждает выпуск и не
описывает установленную alpha.3.

## Будущие выпуски

Опубликованная и установленная alpha.3 остаётся одобренным выпуском. Для
публикации новых профилей исходников требуется существующая проверка выпуска и
перехода установщика. Этот план не меняет правила выпуска.
