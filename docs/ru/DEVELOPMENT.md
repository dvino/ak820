# Разработка

Поддерживаемая цель прошивки находится в `qmk-8051-ak820/keyboards/ajazz/ak820/`,
выбранный keymap — `keymaps/vial`. Дерево QMK сокращено до порта AK820 и нужного
общего кода. Состав каждого образа указан в связанном отчёте сборки.

| Область | Исходники |
| --- | --- |
| Матрица, энкодер и OEM-оборудование | `ak820_board.c`, `matrix.c` |
| Запуск, flash и журнал настроек | `ak820_startup.c`, `ak820_flash.c`, `ak820_nvm.c` |
| Макросы и RGB | `ak820_macro.c`, `ak820_rgb.c`; выходы C/W описаны в [индикаторах](INDICATORS.md) |
| Tap-hold, Repeat и Alt Repeat | `ak820_tapping.c`, `ak820_tapping.h`; поведение описано в [Tap-hold](TAP-HOLD.md) |
| Комбинации двух клавиш | `ak820_combo.c`, `ak820_combo.h`; поведение описано в [Combos](COMBOS.md) |
| Сборка и упаковка образа | `qmk-8051-ak820/util/` |
| Установщик и его тесты | `tools/installer/` |
| Регрессии runtime и CPU | `qmk-8051-ak820/tests/ak820_*` |

Перед изменениями прочитайте `AGENTS.md`. Поведение, команды, форматы, размеры,
адреса, API и ограничения документируйте на английском и русском. Поддерживайте
в актуальном состоянии README и [статус](STATUS.md); будущие задачи описывайте в
[плане](ROADMAP.md). Перегенерируйте затронутые отчёты и сверяйте их значения с
артефактами.

Разделяйте исходники, собранное приложение, пакет выпуска и установленную
прошивку. Отдельно указывайте host/CPU-проверки, сборки и проверки устройства.
Успех на одном уровне не доказывает другой. Во время офлайн-проверок команды
устройству не отправляются. Для каждой прошивки нужно явное подтверждение.

Перед коммитом независимый рецензент проверяет код, документацию и результаты.
Разногласия нужно устранить, закрытие замечаний записать и повторить затронутые
проверки. Сохраняйте границы загрузчика и защищённой ROM, проверку точного образа,
согласие и данные восстановления. Не включайте частные ROM и снимки пользователя.
