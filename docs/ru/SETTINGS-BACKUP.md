# Сохранение и восстановление настроек

**В beta.5 запись настроек не разрешена.** Утверждение каталога, распознавание
образа и офлайн-проверка переноса не разрешают восстановление или перенос
настроек. Ниже восстановление описано на случай, если запись будет разрешена.

Для сохранения настроек используйте сценарий установщика на Python. При
разрешённом восстановлении он проверяет точный образ прошивки и останавливается,
если сохранённые данные не поддерживаются. Восстановление настроек не меняет выбранный профиль
и не сохраняет Direct-цвета в EEPROM. Для выбранного профиля нужен полный,
точно утверждённый комплект файлов релиза. Отсутствующий либо несовместимый
каталог/подтверждение beta.5 блокирует восстановление до обращения к USB;
старый образ не подставляется автоматически.

При разрешённом восстановлении закройте другие программы для клавиатуры и не
нажимайте клавиши, не сбрасывайте клавиатуру и не переводите её в загрузчик.
Открытое HID-соединение не блокирует другие программы: отдельная команда raw-HID
может изменить маркер загрузчика после проверки образа. Адаптер не устраняет
эту гонку. При ошибке транспорта операция останавливается; не повторяйте
запись и не восстанавливайте данные вслепую.

## Запуск сценария

Используйте `tools/installer/ak820.py` из исходников или соответствующий пакет
релиза для Windows либо Linux x86_64. Сначала установите указанную зависимость
Python. В Windows запускайте через `py -3`, в Linux — через `python3`.

```sh
python3 tools/installer/ak820.py --profile main backup --help
python3 tools/installer/ak820.py --profile main restore --help
```

Укажите пути в аргументах: `backup --session OEM_DIR --output BACKUP_DIR`
использует исходный личный сеанс восстановления OEM (`permanent-session`
внутри папки сеанса установки) и отдельную папку копии настроек. Если запись настроек будет разрешена, для восстановления используется
`restore --session OEM_DIR --backup BACKUP_DIR`. Это подкоманды сценария; после
установки пакета используйте `AK820.cmd` в Windows или `./AK820.sh` в Linux.
Копия настроек не заменяет файлы восстановления OEM. Храните их отдельно от
исходников и не публикуйте. Подготовка описана в разделе [Установка](INSTALL.md).

## Содержимое копии

Копия настроек содержит назначения клавиш и энкодера, макросы, поддерживаемые
параметры и настройки RGB. Типизированный формат схемы 03 также сохраняет
поддерживаемые данные расширений. Перед восстановлением проверяются точные образы
и разрешённые переходы. Неподдерживаемые коды клавиш, записи расширений,
параметры или переходы профилей останавливают восстановление до первой записи.

Цвета Direct хранятся только в оперативной памяти. Для точного образа с Direct
v1 и успешным согласованием протокола создаётся отдельный файл `direct-ram.json`
с 82 значениями HSV8 и метаданными формата. Экспорт настроек не замораживает
состояние RAM и NVM одновременно.

Отдельный API `restore_direct_palette` восстанавливает эту копию только при
явном разрешении записи, после проверки точного образа и возможностей протокола
и чтения свежего поколения палитры. Он фиксирует полный кадр и проверяет его
повторным чтением. API не включает режим Direct и не сохраняет палитру в EEPROM.
Старые копии без этого файла не восстанавливают Direct-цвета. Протокол и
ограничения описаны в разделе [Direct](DIRECT.md).

В исходной опубликованной beta.5 распознаются настройки точных опубликованных образов beta.3, beta.4,
beta.4.1 и beta.5; целевой образ должен быть из beta.5. Распознавание и
офлайн-проверка переходов не разрешают запись настроек: в каталоге beta.5
`settings_writes_authorized` остаётся false. Другие выпуски не поддерживаются.
Переходы между профилями текущего выпуска должны
быть указаны явно и пройти проверку схемы, функций и значений. Во
время копирования закройте программы настройки: прошивка продолжает работать
при чтении параметров. При ошибке чтения, тайм-ауте или несовпадении операция
останавливается.

Текущий кандидат не прошёл квалификацию. Источниками настроек для него
допускаются только аутентифицированные идентификаторы образов опубликованных
профилей beta.4.1 и идентификаторы образов собственных текущих профилей;
целевыми могут быть только профили кандидата. Источники beta.3 не допускаются.
Образы beta.4 и beta.4.1 имеют одинаковые идентификаторы образов, поэтому
различить их по идентификатору нельзя. Эта политика не подтверждает
квалификацию кандидата, не разрешает запись настроек и не подтверждает
физическое восстановление.

Формат копий и правила переноса описаны в разделе
[Хранение модулей](MODULE-STORAGE.md). Идентификаторы выпусков и текущее
состояние указаны в [статусе](STATUS.md).
