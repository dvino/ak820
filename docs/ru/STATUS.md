# Состояние проекта

Обновлено 2026-10-24. В исходниках разработки реализован компактный
Mod-Tap/Layer-Tap. Последняя сборка закреплённым SDCC 4.6.0 оставляет 24 байта
в конце CODE. Полный офлайн-прогон прошёл после исправления удержаний Grave Escape.
Отслеживаемый комплект установщика содержит прежнюю прошивку. CI собирает
прошивку сам и передаёт её в упаковку Windows. Записи прошивки и настроек
в устройство в этой работе не выполнялись.

## Сохранённое сравнение выпуска и правки указателя

| Измерение | Сохранённый контроль выпуска | Повторно собранный кандидат |
| --- | ---: | ---: |
| Занятые байты CODE | 38 100 | 38 069 |
| Основное / нижнее окно CODE | 36 292 / 1808 | 36 261 / 1808 |
| Байты XRAM | 2067 | 2066 |
| Начальный SP / выделенная ёмкость стека | 0x62 / 157 байт | 0x62 / 157 байт |

В этом прежнем сравнении правка затрагивала только XDATA-указатель в закрытой функции
проверки заголовка журнала. Формат журнала, CRC, порядок восстановления,
шесть слоёв и 16 макросов с общим хранилищем 8192 байта сохранены. Кандидат
экономит 31 байт CODE и один байт XRAM. Проверенная функция использует четыре
байта стека вместо шести; это не предел для всех путей выполнения и наложения
прерываний. Проба замены выражения задержки добавила три байта CODE и отклонена.
Подробности — в [отчёте пробы](../../audits/rc6/bounded-optimization-20261023.md)
и [описании памяти](RESOURCE-BUDGET.md).

Точные SHA256 IHX приложения:

- Отслеживаемый выпуск и профиль установленного образа: `f1c4347e60ca5f7ea6c557debe60272259f4ddf9acfac9897fa992210bf7ef2e`.
- Прежний кандидат только с правкой указателя: `feac6dae864e801b6177fb8c57a23a65c59b850c5dd3ce84dfb2abb853058cc8`.

Кандидат не установлен. Его IHX — приложение, а не полный ROM для прошивки.
Для создания полного образа обновления по-прежнему нужны локальные OEM-данные
восстановления. Проверенные модели настроек поддерживают восстановление
в ту же сборку и явный переход от прежнего образа к кандидату. Обратный
переход и неизвестные образы запрещены. На клавиатуре такой переход
не проверялся.

## Текущие проверки

Компактная реализация Mod-Tap/Layer-Tap остаётся кандидатом разработки.
После исправления Grave Escape сборка оставляет 24 байта до `0xc700`.
В образе 40 399 заполненных байт CODE, XRAM — 2512 байт, выделенный стек —
157 байт. IHX: `d5842186152b0a612289775c89cc8564167cb8f0bb0b2cc34858a37dda7b8fd3`. Обновление не установлено.
Последний исправленный образ прошёл все 65 сценариев tap-hold, а также
отдельные 33 проверки функций, 10 разблокировки и 16 Tri Layer.
Первый прогон провалился из-за неверного предположения о ветке сброса в тесте
отмены; исправление теста прошло независимое ревью. Отмена проверена через
явно описанное вмешательство симулятора, без выполнения EEPROM/сброса. Первый полный прогон из 26 наборов также обнаружил настоящий дефект
учёта удержаний и кеша Grave Escape и старые предположения тестов о слоях
и слабых модификаторах. Код и тесты исправлены и независимо проверены.
[Свежий полный прогон из 26 наборов](../../audits/rc6/compact-tapping-qualification-20261024/qualification.json)
прошёл: 258 юнит-тестов, без пропусков, хеши IHX/MAP не менялись. Прежний
проваленный отчёт сохранён. [Независимое офлайн-ревью](../../audits/rc6/compact-tapping-final-integration-review-20261024.md)
пройдено. [Проверка свежего комплекта](../../audits/rc6/compact-tapping-fresh-bundle-20261024/check.json)
из коммита `3c96e37` также прошла: установщик принял созданный пакет с точными
проверками допуска, без доступа к HID. Для dev CI нужна авторизация GitHub. Приведённые ниже результаты 23 наборов относятся к предыдущему
сохранённому образу, а не к этому кандидату.

[Чистый локальный прогон](../../audits/rc6/ci-integration-20261023/qualification.json)
прошёл все **23 набора**, включая **257 юнит-тестов без пропусков**, восемь
host C и шесть CPU-наборов. Хеши IHX и MAP не менялись. Отдельный запуск всех
юнит-тестов host-инструментов прошёл 109 тестов; выбор версии компилятора —
три теста. Эти числа пересекаются с общим прогоном и не складываются
в количество разных тестов.

Синтаксис проверен в 208 отслеживаемых Python-файлах и одном shell-файле.
Actionlint прошёл. Ruff не нашёл ошибок по выбранным правилам: повтор ключей
словаря, assert с кортежем и неопределённые имена. Прежние предупреждения
о последовательностях экранирования в upstream QMK Python записаны отдельно.
Локальный прогон использует `ASAN_OPTIONS=detect_leaks=0`: проверки адресов
и неопределённого поведения включены в использующих их тестах, но утечки
памяти локально не проверялись.

Первая проверка импорта не уложилась в 20 секунд GUI-теста; LUFA отсутствовал.
Теперь GUI-модель выполняется в дочернем процессе с ограниченным временем
ожидания, остановкой и ожиданием завершения. Ещё один прогон во время правок
сохранён как неуспешный; его заменяет чистый результат выше. До одобрения
комплекта CI проверяет точный состав обязательных наборов и параметры CPU/IAP.

Отдельная [проверка устройства чтением](../../audits/rc6/ci-integration-20261023/readonly-summary.json)
прошла на прежней прошивке: проверены 498 назначений клавиш, 12 назначений
энкодера, 16 макросов через представление на 8192 байта и 82 RGB-описателя.
Изменение настроек, сохранение RGB и физическая работа пропущены. Доступ udev
и Linux-backend hidraw работали. Исходная команда setup теперь явно собирает
этот backend и не использует кеш колёс с другим backend.

[Манифест доказательств](../../audits/rc6/ci-integration-20261023/evidence-manifest.json)
связывает сохранённый локальный отчёт и консольные журналы. Полные журналы
симулятора этого прогона и приватные снимки устройства остаются вне Git.
Прежняя квалификация с 247 юнит-тестами сохранена в
[старом прогоне](../../audits/rc6/roadmap-qualification-20261023/final/report.json):
она относится к исходникам до CI-работы, а не к текущему host-коду.

## CI, упаковка и формы Issues

Каждый push ветки и pull request запускает проверки и сборки. `dev` и `main`
без тега создают артефакты. Новый SemVer-тег на коммите из `main` публикует
релиз только после успешных задач Linux и Windows; предварительные версии
получают соответствующую отметку. Windows получает прошивку из той же
Linux-задачи. Перед публикацией проверяется, что обе папки приложений
содержат именно этот новый комплект. Точная схема и правило ревью описаны
в [CI и выпусках](CI.md).

Локальные проверки правила CI и упаковки используют точного кандидата
и проверенные приватные OEM-данные. В Git попадают только хеши и очищенные
результаты упаковки; CI применяет их к повторно собранной программе.
Машинный отчёт сборки отличается от независимого ревью и не разрешает
обращение к устройству.

Текущее одобрение исходников связывает 21 host-файл. SHA256 отслеживаемого
манифеста прежнего выпуска:
`234d7d7d267bc2b5dd61faa63d00543366b0db2208407631053c8b73f91055db`.
[Запись ревью](../../releases/rc6/reviews/independent-review.md) различает
прежнюю прошивку и обновлённый host-код. Исходная команда verify прошла
без загрузки HID и открытия USB. [Прогон GitHub 40007909621](https://github.com/dvino/ak820/actions/runs/40007909621)
прошёл на коммите `4f55c59a7307c80f22888dd043b508cd7bef0416`: Linux собрал
прошивку и прошёл все проверки; Windows собрал оба приложения с этой новой
прошивкой и прошёл проверки упаковки, CLI и запуска Tk. Загружены три артефакта.
Публикация штатно пропущена: это push в `dev` без тега. Видимые диалоги и работа
устройства не проверялись. Журналы задач и сведения об артефактах сохранены
в [каталоге результатов](../../audits/rc6/ci-integration-20261023/github-run.json).

Подготовлены три GitHub Issue Forms: ошибка, предложение функции и проблема
прошивки/восстановления. YAML и документы проверены, независимое ревью закрыло
исправление ссылки на выбор формы. V2, Pro и Max исключены; запрашиваются
очищенные журналы, а не OEM ROM или приватные копии. Формы закоммичены отдельно
в `main`; на сервере проверен коммит `15ca3bce33866d5d8d7828f4f23338180ac94dad`.

## Прежние проверки устройства и оставшаяся работа

Прежние данные установки содержат SHA256 payload
`a1b8beec9a2a675c955bac946339e31f1823e17cdfb60f4755796e550530c711` и полного ROM
`56b2de776924c48bda6d08a2604edc8ab94f24e5ec7365f7b584c0fe7dd70fc5`.
Проверены CODE, манифест, защищённые области, начальный NVM и чистое хранилище
после перезапуска. Физический набор текста подтверждён отдельно. Эти данные
не доказывают новый host-переход и сохранность после полного снятия питания.

Открыты запись настроек на устройстве, загрузка макросов, сохранение RGB,
физическая работа энкодера/подсветки и проверка потери питания. До реализации
C/W нужна доказанная электрическая привязка из OEM-прошивки. Сохранение
палитры Direct отменено; Windows-помощник языка ещё не закончен. Переназначение Caps
и смена языка этой клавишей отложены текущим запросом.
[План](ROADMAP.md) отдельно перечисляет эти задачи и оставшиеся ограниченные
исследования оптимизации.
