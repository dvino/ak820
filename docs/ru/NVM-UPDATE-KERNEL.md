# Ассемблерное обновление блока NVM

Флаг `--nvm-update-block-asm` выбирает отдельный модуль SDCC для функции
`ak820_eeprom_update_block_xdata`. По умолчанию флаг выключен; исходная
функция на C остаётся резервным вариантом. Записыватель, журнал, формат flash
и правила сброса буфера не меняются.

Ядро сравнивает каждый сохранённый байт до чтения соответствующего байта из
XDATA. При первом отличии оно передаёт управление существующему записывателю,
передавая исходный указатель, все три байта generic-адреса и исходную
16-битную длину. Если запрос пустой или байты совпадают, запись не вызывается.
Адрес сравнения оборачивается по 16 битам, как в выражении C `offset + i`.
Адреса за диапазоном проходят через существующий скалярный хук EEPROM, который
возвращает ноль. При отличии сохраняются проверка диапазона для всего запроса
и время отказа записывателя; ядро не повторяет неудачную запись.

## Соглашение вызова и стек

Поддерживается закреплённый SDCC 4.6.0: модель MCS51 large, соглашение вызова
0, банк регистров 0 и фиксированные XDATA-слоты параметров. Двухбайтовый
указатель XDATA поступает в DPTR; generic-адрес и длина занимают обычные пять
байт параметров. Функция обновления должна оставаться вызываемой с обычным
соглашением о временных регистрах. R2–R7, A, B, DPTR и арифметические флаги
используются как временные. Ядро сравнения сохраняет R0/R1; хвостовой вызов
записывателя на C при отличии может их менять в соответствии с обычным
соглашением компилятора. Выбор банка не меняется. Скалярный хук
`eeprom_read_byte` должен сохранять R0–R7. Проверка сборщика не заменяет
проверку реально связанного хука.

Два байта стека хранят исходный указатель. Во время скалярного чтения адрес
возврата добавляет два байта, а текущий путь кэша скалярного чтения может
добавить ещё два. Итого до учёта вынесенных функций и прерываний требуется до
шести байт сверх входного указателя стека. Пустой или совпадающий запрос
освобождает оба частных байта. При несовпадении они освобождаются до перехода
к записывателю, который возвращается прямо исходному вызывающему коду.
Собственный стек записывателя учитывается отдельно. Эти функции и статические
слоты параметров нельзя вызывать рекурсивно или из прерывания, пока они
заняты. Для точного образа обязательны проверки запуска, графа вызовов,
outliner, банков и прерываний.

Сборщик отклоняет неподдерживаемые параметры компилятора для стека,
параметров, модели и соглашения вызова; объявление сохранения регистров
обновляющей функцией; отсутствие проверенного скалярного хука; а также попытки
передать собственное утверждение или флаг функции через дополнительные
параметры. Исходный код также отклоняет несовместимые предопределённые макросы
компилятора.

## Проверка компонента

Запуск из корня репозитория:

```sh
python tests/ak820_nvm_updateasm/policy.py
python tests/ak820_nvm_updateasm/run.py \
  --toolchain /path/to/sdcc-4.6.0 \
  --output outputs/nvm-update-kernel
```

В `outputs/nvm-update-kernel/` сохраняются сгенерированный тестовый стенд,
зафиксированный эталон C, ассемблер, листинги и объектные файлы компилятора,
связанный тестовый образ, журналы и JSON с контрольными суммами. Тест CPU
собирает производственное ядро отдельным модулем и сравнивает его с циклом C.
Скалярная функция и записыватель заменены заглушками: проверка не выполняет
запись во flash и не проверяет сохранность журнала.

Проверяются порядок адресов чтения, вызов записывателя при первом отличии,
исходные аргументы записывателя, все четыре generic-тега указателя, пустые и
совпадающие запросы, границы страниц и NVM, 16-битное переполнение адреса,
защитные байты источника, R0/R1, банк 0 и сбалансированный SP. Заглушка
скалярного чтения меняет текущий байт источника перед возвратом, чтобы
проверить порядок «сначала чтение, затем источник». Заглушка неудачной записи
проверяет передачу управления без повтора. Длины запросов включают 0, 1, 2,
16, 64 и 257; отдельный тест передаёт длину 65535 при несовпадении первого
байта. Полный проход длины 65535 без отличий этот стенд не проверяет.

Все 3 169 парных тестов CPU прошли, включая запрос максимальной длины с
отличием в первом байте. Сравнение отдельных объектов: CSEG 156 против 118
байт, DSEG 7 против 0, XSEG 7 против 5. Для эталона используется эквивалентный
скалярный адаптер EEPROM вместо внутреннего символа `read_offset`, поэтому это
только сравнение компонента. Эти размеры не показывают экономию связанного
образа и не доказывают границу стека всей прошивки или работу на аппаратуре.

В точном связанном образе прошли 48 сравнений ядра с существующим
записывателем при заранее заполненном кэше; отложенные записи позволили
проверить путь без обращения к flash. Компонент прошёл отдельное ревью и
включён в образ 26b. Это проверка связанного кода с ограниченными условиями,
а не аппаратная проверка сохранности данных. Полная конфигурация пока не
проходит регрессии из-за превышения окна CODE и незакрытого контракта IRQ.
Устройство не проверялось и не изменялось.
