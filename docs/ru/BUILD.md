# Сборка прошивки

Нужны Linux x86-64 или Ubuntu WSL, Python 3.11+, Make и GCC.
SDCC 4.6 и LUFA устанавливаются отдельно и не хранятся в Git.
Из корня репозитория один раз установите закреплённые зависимости:

```sh
python3 tools/install_sdcc46_toolchain.py
python3 tools/install_lufa_dependency.py --fetch
```

Скрипты проверяют хэши архивов. Для установки без сети передайте
`--archive /путь/к/архиву`. LUFA без параметров только проверяет локальные файлы.
Установка SDCC из Windows использует Ubuntu WSL. Пользователям следует брать готовый standalone-пакет: в нём уже есть Python
и hidapi. Настройка установщика из исходников описана ниже. Подготовьте отдельное
окружение сборки прошивки:

```sh
cd qmk-8051-ak820
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-ak820-build.txt
.venv/bin/python util/build_ak820.py \
  --sdcc-version 4.6.0 \
  --toolchain ../toolchains/sdcc-4.6.0 \
  --qmk-bin .venv/bin/qmk \
  --build-dir .build/local-1
```

Для контрольной сборки на 4.4 запустите из корня
`python3 tools/install_sdcc44_toolchain.py`, а при сборке из каталога QMK укажите
`--sdcc-version 4.4.0 --toolchain ../toolchains/sdcc-4.4.0`.
Установленные компиляторы остаются локальными зависимостями.

Каждой сборке нужен новый каталог. Отчёт сохраняет зависимости компилятора,
hash исходников и инструментов, команды, CODE/XRAM/IRAM, IHX/MAP/MEM и
`hardware_validated: false`. Пути записываются через `/`. Валидатор понимает
старые Windows-разделители, но отклоняет выход за корни и повторные псевдонимы.

IHX — приложение, не готовый образ для прошивки. Упаковщик добавляет входы
загрузчика, проверяет защищённые области и использует известные reference.
Сборщик выпуска требует `--oem-reference-dir` с локальной парой
`stock-full.bin` и `native-installed.bin`; каталог нужен только для офлайн
проверки и не копируется в выпуск. При первой обычной установке установщик
создаёт приватные файлы сравнения в сессии восстановления из полной
проверенной копии ROM пользователя. Отдельная загрузка reference не нужна.
CODE имеет два отдельных окна `[0x28a0,0x3000)` и `[0x3027,0xc700)`.
NVM/макросы не являются свободным CODE. Считайте занятые байты связанного образа.

## Профили функций

Используйте [конфигуратор профилей](BUILD-PROFILES.md), чтобы собрать одно из
восьми сочетаний функций. Он связывает полный образ, проверяет размещение
ресурсов и запускает автономные регрессионные проверки. Профиль `full` —
кандидат alpha.3; квалификация исходников и независимая проверка правила
выпуска завершены. Кандидат не опубликован, не проверен на устройстве и
ожидает нативного CI. Остальные семь профилей предназначены для разработки.

Сборка использует компактный outliner инструкций с фиксированным списком
разрешённых опкодов и модулей. Параметры `--no-outline` и `--no-callee-saves`
нужны для сравнительных сборок. Outlining меняет связанный образ, но не
является функцией во время работы. Экономию одного образа нельзя переносить на
другие сочетания функций: общий код и упаковка влияют на итог. Изменение ABI
требует новых доказательств по стеку и прерываниям. Не запускайте сборки
параллельно в одном дереве: Make использует общие генерируемые файлы. См.
[измерения outlining](../../audits/rc6/roadmap-max-20261024/outline-speed.md).

После тестов и независимого ревью соберите комплект выпуска из корня
репозитория. Запись ревью должна быть JSON-файлом, связанным с точными IHX, MAP,
отчётом сборки и входами host. Это шаблон команды; укажите локальные пути к
ревью и частным reference, а для результата выберите новый каталог:

```sh
python3 tools/build_release_bundle.py \
  --build-dir qmk-8051-ak820/.build/local-1 \
  --review /path/to/exact-candidate-review.json \
  --oem-reference-dir /path/to/private-oem-references \
  --toolchain toolchains/sdcc-4.6.0 \
  --builder-source qmk-8051-ak820/util/build_ak820.py \
  --output releases/rc6-new
```

`docs/REVIEW.md` содержит ссылки на ревью, но не является записью об одобрении
точной сборки. Упаковка комплекта не разрешает операции с устройством. Изменение
исходников или host-входов делает прежние доказательства неприменимыми. До
проверки установщика и упаковки приложений интегрируйте одобренный комплект в
`releases/rc6`, каталог установщика.

## Windows-приложения установщика

Для нового пакета Windows соберите проверенный выпуск в Windows, используя Python 3.12 и закреплённый
PyInstaller 6.16.0:

```powershell
py -3.12 -m venv .venv-windows-installer
.venv-windows-installer\Scripts\python -m pip install -r tools\installer\requirements-build-windows.txt
.venv-windows-installer\Scripts\python tools\test_build_windows_installer.py
.venv-windows-installer\Scripts\python tools\build_windows_installer.py --output dist\AK820-Windows
```

Команда откажется заменять существующую папку или ZIP. Она соберёт оба
приложения, сверит SHA256 каждого разрешённого файла в обеих полных папках
PyInstaller, запустит справку CLI и офлайн-проверку выпуска, затем создаст и
закроет интерфейс Tk через `--self-test`. Это нативная проверка создания UI,
а не проверка удобства интерактивной работы. В папке будут `AK820/`,
`AK820-cli/`, `AK820.cmd`, `build-provenance.json` и `smoke-report.json`;
соседний `dist/AK820-Windows.zip` сохранит все эти пути. Перед передачей
проверьте оба JSON-отчёта и ZIP. Сборка не перечисляет USB-устройства, не
проверяет физическую клавиатуру и не прошивает её. OEM-файлы, личные копии
резервных данных и журналы сессий исключены.
GitHub Actions собирает и проверяет каждый push ветки и pull request.
Теги версий публикуют пакеты Windows и Linux после успешных проверок прошивки
и приложений обеих систем. Оба пакета используют прошивку из одного запуска CI.
Теги на коммитах main публикуют комплект прошивки, Windows ZIP и Linux tarball. Запуски, артефакты и
правило повторяемой сборки описаны в [CI и выпусках](CI.md).
OEM ROM и личные копии не должны входить в комплект.

## Выбор опубликованной прошивки для исходного установщика

В исходниках сохранён прежний комплект `releases/rc6`. Сборка прошивки и
команда `setup` не заменяют его. Для работы с опубликованным релизом возьмите
чистую копию исходников его тега и скачайте `firmware-bundle.zip` с SHA256
из того же релиза. До распаковки проверьте сумму способом из
[инструкции установки](INSTALL.md), подставив имена файлов комплекта прошивки.

Распакуйте ZIP в новую папку `firmware-bundle`. Каталоги `firmware`, `reports`
и остальные файлы лежат непосредственно в ней. Скопируйте всё содержимое
в `releases/rc6`, затем скопируйте `firmware-bundle/approved-release.json`
в `tools/installer/approved-release.json`. Сохраняйте полный комплект и не
смешивайте файлы разных релизов. Перед командами для устройства выполните
`verify` исходным установщиком, как показано ниже. Одобренный манифест сверяет
выбранные файлы с точным релизом и его host-кодом.

## Установщик из исходников

Следующие команды выполняются из корня репозитория.

Python-окружение установщика отделено от окружения сборки QMK. Нужен Python
3.10 или новее. В Ubuntu/Debian установите системные зависимости, затем
запустите настройку: launcher создаст `.venv-ak820-installer` и установит
закреплённую зависимость `hidapi==0.15.0`.

```sh
sudo apt-get install build-essential python3-dev python3-venv python3-tk libudev-dev
./AK820.sh setup
./AK820.sh udev --install
./AK820.sh verify
.venv-ak820-installer/bin/python tools/installer/gui.py
```

Команда udev устанавливает правило доступа к устройству и перезагружает правила.
Для Windows установите Python 3.10 или новее и выполните команды в PowerShell
из корня репозитория:

```powershell
.\AK820.cmd setup
.\AK820.cmd verify
.\.venv-ak820-installer\Scripts\python.exe tools\installer\gui.py
```

Команды настраивают среду и запускают интерфейс; `verify` проверяет файлы
выпуска офлайн. Прошивка клавиатуры не выполняется. Пользователям удобнее
скачать standalone-пакет для Windows или Linux: Python устанавливать не нужно.

## Нативный установщик Linux

Для standalone-пакета используйте Ubuntu 22.04 x86_64 и Python 3.12. Нужны
системные зависимости `python3-dev`, `python3-tk`, `libudev-dev`,
`libusb-1.0-0-dev`, `build-essential`, `xvfb` и `xauth`. Из корня репозитория
выполните команды:

```sh
HIDAPI_WITH_HIDRAW=1 HIDAPI_WITH_LIBUSB=0 \
  python3 -m pip install --no-binary=hidapi -r tools/installer/requirements-build-linux.txt
python3 -B -m unittest discover -s tools -p test_build_linux_installer.py
python3 tools/build_linux_installer.py --output dist/AK820-Linux-x86_64
(cd dist && sha256sum AK820-Linux-x86_64.tar.gz > AK820-Linux-x86_64.tar.gz.sha256)
```

Сборщик откажется перезаписывать существующий результат или рабочую папку. Он
проверит hidraw, справку CLI, офлайн-проверку выпуска и запуск Tk под Xvfb,
затем создаст tar.gz. Проверки не открывают USB и не подтверждают работу
клавиатуры. CI берёт свежую прошивку и публикует пакет с SHA256.
