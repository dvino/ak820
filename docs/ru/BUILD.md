# Сборка прошивки

Нужны Linux x86-64 или Ubuntu WSL, Python 3.11+, Make и GCC.
SDCC 4.6 и LUFA устанавливаются отдельно и не хранятся в Git.
Из корня репозитория один раз установите закреплённые зависимости:

```sh
python3 tools/install_sdcc46_toolchain.py
python3 tools/install_lufa_dependency.py --fetch
```

Скрипты проверяют хэши архивов. Для установки без сети передайте
`--archive /путь/к/архиву`. LUFA без параметров только проверяет локальные файлы.
Установка SDCC из Windows использует Ubuntu WSL. Установщику из исходников нужны
Python 3.10+ и собственные зависимости. Подготовьте окружение сборки:

```sh
cd qmk-8051-ak820
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-ak820-build.txt
.venv/bin/python util/build_ak820.py \
  --sdcc-version 4.6.0 \
  --toolchain ../toolchains/sdcc-4.6.0 \
  --qmk-bin .venv/bin/qmk \
  --build-dir .build/local-1
```

Для контрольной сборки на 4.4 запустите из корня
`python3 tools/install_sdcc44_toolchain.py`, а при сборке из каталога QMK укажите
`--sdcc-version 4.4.0 --toolchain ../toolchains/sdcc-4.4.0`.
Установленные компиляторы остаются локальными зависимостями.

Каждой сборке нужен новый каталог. Отчёт сохраняет зависимости компилятора,
hash исходников и инструментов, команды, CODE/XRAM/IRAM, IHX/MAP/MEM и
`hardware_validated: false`. Пути записываются через `/`. Валидатор понимает
старые Windows-разделители, но отклоняет выход за корни и повторные псевдонимы.

IHX — приложение, не готовый образ для прошивки. Упаковщик добавляет входы
загрузчика, проверяет защищённые области и использует известные reference.
Сборщик выпуска требует `--oem-reference-dir` с локальной парой
`stock-full.bin` и `native-installed.bin`; каталог нужен только для офлайн
проверки и не копируется в выпуск. При первой обычной установке установщик
создаёт приватные файлы сравнения в сессии восстановления из полной
проверенной копии ROM пользователя. Отдельная загрузка reference не нужна.
CODE имеет два отдельных окна `[0x28a0,0x3000)` и `[0x3027,0xc700)`.
NVM/макросы не являются свободным CODE. Считайте занятые байты связанного образа.

Для сравнения есть `--no-outline` и `--no-callee-saves`. Изменение ABI требует
новых проверок стека и прерываний. Не запускайте сборки параллельно в одном
дереве: Make использует общие генерируемые файлы.

После тестов и независимого ревью комплект собирает
`tools/build_release_bundle.py --build-dir .build/local-1 --review docs/REVIEW.md --oem-reference-dir /path/to/private-oem-references --toolchain toolchains/sdcc-4.6.0 --builder-source qmk-8051-ak820/util/build_ak820.py --output releases/rc6-new`.
Команду упаковки запускайте из корня репозитория.
Пример пути указывает на собственную локальную пару. Ревью связывается с
точными IHX/MAP, отчётом и host inputs. Упаковка не разрешает аппаратную
запись. Изменение входов делает прежние доказательства неприменимыми. После
ревью новый комплект нужно интегрировать в `releases/rc6`, откуда установщик
берёт комплект, до запуска его проверки и сборки Windows-приложений.

## Windows-приложения установщика

Текущий проверенный комплект: `dist/AK820-sdcc46-breathing-20261023/`, полные папки
`AK820/` и `AK820-cli/`. Одного EXE недостаточно. Python уже включён;
исходному wrapper нужен Python 3.10+.

Команда: `tools/build_windows_installer.py --output dist/AK820-sdcc46-breathing-20261023`.
Лог: `host/runs/20261023-sdcc46-windows.json`, результат процесса:
`host/runs/20261023-sdcc46-windows.json`.
Справка CLI, офлайн-проверка и self-test GUI прошли.
[Независимая проверка](../../audits/rc6/sdcc46-release-review-20261023.md)
содержит результаты проверки комплекта. Результат устройства —
в [статусе](STATUS.md).

Прежние папки GUI и `dist/AK820-RC6-Windows-20261023.zip` неактуальны.
Для этого кандидата их не использовать. Локальный ZIP:
`dist/AK820-sdcc46-breathing-20261023.zip`. Публичной загрузки нет.
OEM ROM и личные копии не должны входить в комплект.
